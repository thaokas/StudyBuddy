# T03：双主栏方案验证

> 任务卡只写要求；状态以 [STATUS](../STATUS.md) 为准。开工前先读 [AGENT.md](../AGENT.md)。

- 预计：0.5 个会话
- 依赖：T02
- 波次：W3
- 状态：见 [STATUS](../STATUS.md) 的 T03 行

## 目标

用实测回答"学习工作台与对话能否并列"，给出成本最低的可行方案（目标：左侧学习、右侧对话）。

## 所有权（只能改这些路径）

- `probes/layout/**`
- `docs/decisions/layout.md`

## 交付

- 路线 1 零补丁：`ctx.sidebarRightTabs` + `sidebar.right.pane.tab` 注册宽面板，测宽度上限、无会话时是否可用、重启恢复。
- 路线 2 复用第三方：隔离 profile 安装 `dock`（`ctx.workbench`），看能否与原生聊天并存、可停靠/悬浮。
- 路线 3 最小核心补丁：只读评估 `AppFrame` 增加第二主栏槽的成本（测试、locale、快照、升级重放）。
- 结论、截图、选定方案、补丁行数估算与回退方式。

## 验收

- 1440×900 下至少一条路"学习区 + 对话区"同时可见且可操作。
- 明确"无会话打开时学习区是否仍在"。
- 给出选定方案与成本；无结论不算完成。

## 不做

- 正式实现。
- 修改 DSH 源码（路线 3 只评估）。

## 开工前

1. 读 [AGENT.md](../AGENT.md)，确认工程约定与完成标准。
2. 在 [STATUS](../STATUS.md) 确认依赖 T02 均为 DONE；不满足就停下并在 STATUS 写 BLOCKED。
3. 只改"所有权"里的路径；需要共享文件时按 AGENT.md 串行处理。
4. 先写测试或证据脚本，再改实现。

## 完成后

1. 跑测试，记录命令与真实结果（失败也要写）。
2. 把 STATUS 的 T03 行改为 DONE / REVIEW / BLOCKED，填证据与已知限制。
3. 不修改其他任务的状态，不顺手重构无关代码。
