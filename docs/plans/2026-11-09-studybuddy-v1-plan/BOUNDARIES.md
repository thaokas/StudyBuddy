本文件是 [STATUS.md](STATUS.md) 第 5 节的独立版：逐条记录已冻结的内核/服务/客户端契约、各任务的已知限制与不变量。STATUS 只保留状态与证据，边界细节看这里。

## 5. 已知边界（随任务补充）

- **外层工作区没有 Git**：任务隔离依靠目录所有权与 STATUS 记录，不能用分支或 worktree；`source/deepseek-harness` 自身在 `task/studybuddy-model-config` 分支且改动未提交。
- **源码处于该任务分支且未提交**；`patches/0001` 是当前工作树快照，源码继续改动后必须重新生成并重跑反向校验。
- 提醒仅在应用运行时生效；关闭应用不触发，也不补发。
- v1 无升级器，设计场景 14 只做到"冷备份 + 恢复匹配程序"，标记为部分覆盖。
- 生成插件与普通插件同权限，不是沙箱；不得对外宣称受限执行。
- 手写 client loader 与自动发现沿用上游测试夹具形态，DSH 升级需回归一次。
- 桌面冒烟依赖本机 GUI 与调试端口：需要宿主权限，窗口关闭会让应用退出。
- 新增核心补丁必须登记进 `patches/README.md` 并更新 PLAN 3.4 的预算表。
- **T01 内核契约（已冻结）**：`host/modules/*.mjs` 导出 `{ id, deps, schemaVersion, schema, apply(ctx, kernel) }`；服务实现用 `{ methods, writes }` 注册，`writes` 里声明的方法才会 bump revision 并写 `request_log`。未声明却改了数据库的方法只会在日志里告警，不会被当作写操作记录。
- **revision 是全局单计数器**：任何成功写都会让其它命名空间的 `expectedRevision` 过期。需要实体级版本时由模块自带字段，不要改内核语义。
- **`day_snapshot` 每个本地日期只写一次**，触发器禁止 UPDATE/DELETE。后续需要"当天可变的快照"时应新建表，不要改这一行。
- **`request_log` 只增不清理**：T17 做冷备份与导出时再定保留策略。
- **schema 版本不一致是双层保护**：插件加载时拒绝启动并在错误里给出备份路径与恢复步骤；内核层也对写操作返回 `unavailable`。复现见 `plugins/study/tests/kernel/{db,kernel}.test.mjs`。
- **连接是可选的**：web/desktop 提供 `connection` 时按方法注册 `POST /api/study/<ns>/<method>`（仅本机已鉴权 owner 可调，匿名 401）；headless 等无 `connection` 的 profile 仍加载插件并提供 `tools` 与 `ctx.study`，只是没有 HTTP 路由。
- **T01 只有只读工具** `study_status`；T08 起新增业务写工具 `study_materials`（导入/检索，仍只经 `ctx.study.call`），写操作、幂等与重启回读由 service 测试覆盖，不提前发明内核写接口。
- 插件数据目录由 `scripts/project-config.mjs` 传入（`.studybuddy/study`，即 `<root>/study/study.db`）；直接调用 `apply` 时按 `dataDir` → `STUDYBUDDY_STUDY_DIR` → `DSH_HOME/study` 兜底。
- **T08 只记录来源能证明的定位**：chunk 的 `page`/`chapter` 只来自 PDF 页对象、`\f` 分页、`第 N 页` 标记、markdown 或 `第X章` 标题，以及学生显式声明的章节；其余列在 `unverified`（chunk/hit）与 `missing`（资料）里。`materials.locate` 对找不到的章节/页码/题号返回 `unverified` 与原因，不补页码、不猜题号。
- **T08 的 PDF 只读文字层**：支持 Flate/ASCIIHex/ASCII85、对象流（ObjStm）与 ToUnicode（含中文双字节 CID 字体）；扫描件返回 `pdf_no_text_layer`、加密 `pdf_encrypted`、缺 Unicode 映射 `pdf_text_encoding_unsupported`、结构损坏 `pdf_invalid`，均带 `hint`。不支持 LZW/JPX 等压缩，表单 XObject 内的文字暂不解析；部分页无文字时导入其余页并给 `pdf_pages_without_text` 警告。
- **T08 检索是词法而非向量**：中文按重叠 bigram、ASCII 按词建 FTS5 索引；不足两个字符的查询走整串包含匹配。每次最多为 200 个候选打分，极宽泛的查询只返回该窗口内的分页结果；不承诺召回全库。
- **`study_materials` 工具只导入文字**：PDF 与本地文件走 `materials.importFile`（`path` 或 `base64`+`name`），工具本身不读文件系统。文本文件非 UTF-8 时先尝试 GB18030 并给 `decoded_as_gb18030` 警告，失败则报 `text_encoding_unsupported`。
- **T08 跨目录改动**：按用户 2026-11-10 确认，把 `plugins/study/tests/kernel/plugin.test.mjs` 中 5 处写死"只有 kernel 模块/工具/路由"的断言改成按名查找，否则"加文件即注册"必然使旧断言失败；内核行为未改。
- **T20 不接入 `@restregular/dsh-memory`**：隔离 profile 的 spike 全过（见 `evidence/T20-memory-plugin-spike.json`），但它只存 `source.origin`、没有删除墓碑、JSONL 写入绕过 `ctx.study` 的 requestId/revision/change_log，且零代码接入要改启动器或 profile 清单；结论与理由见 `docs/decisions/memory.md`。
- **T20 记忆落在 `memory.json`**：与 `study.db` 同目录；原子替换写（tmp + rename），文件缺失视为空，JSON 损坏/版本未知报 `unavailable` 并停止读写，不静默重置。上限 200 条、正文 500 字、墓碑 500 条。
- **T20 删除抑制**：`forget` 写 `tombstones[{contentHash}]`（只存 hash，不存被删正文）；同内容再次 `remember` 返回 `suppressed`，只有 `actor: "ui"` 且显式 `revokeTombstone: true` 能恢复。v1.1 自动提取必须先查墓碑。
- **T20 会话注入**：`systemPrompt.context({ name: 'study:memory', order: 500 })`，最多 8 条、每条 120 字，只含未过期条目；DSH 的 runtime-context 只在文本变化时写一条 user 快照。
- **T20 中文召回是词法**：字符 + 双字 bigram + 拉丁词加权，阈值 0.35，kind 标签参与匹配；不声称语义检索，向量按任务卡留到 v1.1。
- **T20 跨存储非原子**：`memory.json` 在 SQLite 事务内写入；若随后的 revision 写入失败，文件会领先 revision。失败面只剩这一步，但严格意义上不是跨存储原子提交。
- **T20 新增 `client/messages/memory.js`**：T02 的 `build-client.mjs` 强制 `client/pages/<name>.js` 与 `client/messages/<name>.js` 同名配对；页面仍只在 T20 所有权内，字典是该页面文案的必需文件。
- **T02 页面与动作契约**：`client/pages/<key>.js` 默认导出 `{ key, order, label, Page }`，`key` 必须等于文件名，`label` 是文案键；`client/messages/<key>.js` 必须同名配对（额外字典文件如 `common.js` 允许共享）；`client/actions/*.js` 默认导出 `{ id, page?, label, run }`，省略 `page` 表示所有页面可见。构建先写 `client/.build/entry.js`，由 `client/plugin.js` 统一校验：缺键、重名、`key` 与文件名不符都会让 bundle 加载失败，不会半页渲染。
- **T02 产物与注册**：`exports["./client"]` 指向构建产物 `plugins/study/client/client.js`；`window.__ModuleLoader__.load({ id })` 的 id 必须等于包名 `@studybuddy/study`（DSH 按包名查注册）。改了 `client/**` 后必须重跑 `node plugins/study/scripts/build-client.mjs`；`start-studybuddy.mjs` 暂不代跑构建（T18 收进发布流程）。bundle 新鲜度由 `tests/client/build.test.mjs` 比对，源码与产物不一致就失败。
- **T02 没有本地依赖安装**：`plugins/study/package.json` 只声明 `devDependencies.esbuild`，实际解析顺序是 `plugins/study/node_modules` → 固定源码树 → 源码树的 pnpm store；没有新增 lockfile。
- **T02 语言面**：只有 zh/en 两套字典，且键集合必须一致（`mergeMessages` 校验）；服务端错误文本来自 T01（中文），英文界面下的服务失败信息仍是中文，这是已知限制。
- **T02 UI 冒烟是证据脚本不是单测**：需要 Edge 与宿主进程权限，因此不匹配 `node --test` 的测试文件名；它按学生路径关掉首屏「预览版说明 → 添加 API Key → 稍后配置」链条，否则遮罩会拦住点击。`--keep` 保留临时 home 便于排查。
- **T02 构建自动发现所有页面**：T20 的 `memory` 页面也随本次产物打包（`pages: memory, today`），T02 未修改该文件；页面文案扫描因此覆盖整个 `client/pages`，后续任务新增页面时同样受约束。
- **T05 任务与时间块分离**：任务是全局的稳定实体（`task_<uuid>`），时间块描述日期/起止/固定或弹性/关联任务；一个任务可排多块，改日期、改时间、跨周展示都不改任务 id。固定块（课程/休息）单列在 `summary.fixed`，其分钟与关联任务都不得进入 `summary.study`；任务进度状态机、保存量与冲突检测属于 T06。
- **T05 删除语义**：任务软删除，已有时间块保留并把 `block.task.deleted` 标为 true；仍有活动任务把它当前置时拒绝删除并返回 `conflict` 与 dependents。时间块硬删除，历史靠追加式 `change_log`，且删除本身不静默成功。
- **T05 时间与日期约束**：日期为本地 `YYYY-MM-DD`，周视图固定周一到周日；时间块不跨夜（`end` 必须晚于 `start`），只允许结束为 `24:00`。重叠与超载检测不在本任务，T06 接入后即使允许风险保留也要保持警示。
- **T05 跨目录改动**：新增 `client/messages/workbench.js`（T02 强制页面同名配对）；把 `tests/kernel/plugin.test.mjs` 里"启动后注册 tasks 命名空间"的示例改为尚未占用的 `timer`，否则新模块会让旧用例报"命名空间已注册"；`client/client.js`、`client/.build/entry.js` 是构建产物，本次已重跑生成。
- **T05 的 UI 冒烟边界**：现有 `ui-smoke.mjs` 仍只驱动 `today` 页，验证的是真实 Host+Edge 下整个 bundle 加载、中英切换、刷新与停用；workbench 的今日/周四态、表单和乐观回滚由纯视图测试覆盖，真实点击级 workbench 冒烟留给 T06/T19 的全场景回归。
- **T09 计划数据与版本**：四张表 `study_plan`（头）、`study_plan_revision`（已应用修订快照）、`study_plan_draft`（每个计划至多一份草案）、`study_plan_progress`（追加式进度）。草案是整份 JSON 的全量替换，确认/修订/撤销各追加一条不可变修订；撤销只接受最近一次已应用修订（否则 `undo_not_latest`），生成新修订并把被撤销修订标 `undone`，不删除任何进度行。存在未确认草案时，`revise`/`undo` 必须带上已读取的 `draftId`，否则返回 `conflict` + `draft_pending` 与最新版本，防止 Agent 晚间重排静默覆盖学生刚改的草案。过期草案/确认/修订/撤销统一返回 `conflict`，`details.latest` 带最新 plan/applied/draft/capacity 与最近 5 条修订；内核 `expectedRevision` 仍是整库计数器，命中时只有内核的 expected/current revision。
- **T09 容量口径**：可用时间取草案按日声明的 `availability[].minutes`；未声明且计划绑定目标时回退目标的 `daily_minutes`（否则 `unknown_availability`）。排不下或时间重叠的草案可以保存，但确认/修订必须显式 `trial: true`（`reviewAt` 默认 7 天后或考试期限，取较早者）；排不下的工作保留为 `date: null` 的未安排条目，不自动删除、不自动挪动，也不会伪造“全部排下”。前置任务排在依赖项之后会阻止确认/修订（`dependency_order`），不能靠试行绕过；`constraints`/`assumptions` 只存储文本，不解析执行。
- **T09 与 T05/T06 的边界**：plan item 只存在于计划修订快照里，**不创建** `study_task`/`study_time_block`；计划进度也只写 `study_plan_progress`，与 T06 的任务进度是两套事实。T10/T12 若要驱动工作台，需要自己决定如何把 plan item 物化为任务（T09 不写别的模块的表）。本任务也不写 `day_snapshot`；T13 的“原计划/调整后”口径应读 `study_plan_revision` 的 `applied_at` 与 `change_log`，而不是当天快照。进度只追加（触发器禁 UPDATE/DELETE），取消项单独计数、不进完成项，未记录（`unrecorded`）不等于未学习。
- **T09 幂等与规模**：`requestId` 只在显式传入时生效；工具不再用 DSH `callId` 兜底，避免跨会话 call id 复用把不同内容误判为同 ID 冲突。没有 requestId 时，草案重复保存会覆盖同一 draft，确认/修订会因 `baseRevision` 过期被拒，进度反馈可能重复。每计划最多 500 个任务、100 个阶段目标、100 个周目标、366 天可用时间；进度历史单次最多最后 500 条；依赖可写任务 id 或唯一标题，标题不唯一时要求改 id；工具 `plan` 是一次性 JSON 全量内容，不支持打补丁式部分更新。
- **T15 的完成信号**：唯一触发是 `ctx.sessions.list` 里某行 `running` 由 true 变 false（`api-session/status` 的实时推送会更新它），不读会话日志、不猜轮次。因此**应用关闭或页面加载期间结束的轮次不会补发**；第一次快照直接视为基线，只记录、不宣布。subagent 会话（`origin: 'subagent'`）不提醒。
- **T15 不打扰“你正在看的那一条”**：`retainedBy.mainView > 0`（该会话就是主视图）时跳过提醒；切换到学习页或别的会话后完成才提醒。代价是“盯着回复看”时没有提示，这是有意的；若 T04 双主栏让对话常驻主视图，提醒将几乎不触发，需在 T04/T19 复核该口径。
- **T15 合并与去重**：1.2s 合并窗口内的多个完成合成 1 条（页内条列出每个会话，可单独点开；系统通知固定 tag `study.completion`，后一条替换前一条，点击打开最近完成的会话）；页内条 8s 自动消失，也可「知道了」。去重台账放在 `sessionStorage` 的 `study.notify.completion.announced`（`{version:1, sessions:{<sessionId>:<该轮 updatedAt>}}`，最多 100 条），按“会话 + 该轮活动时间”记账，所以刷新、重挂载、重复状态帧都不会重复宣布，而下一轮新的 `updatedAt` 会重新提醒。
- **T15 权限与降级**：浏览器不支持时 `osStatus=unsupported`、拒绝时 `denied`，**页内提示条都照常出现**并写明“系统通知不可用”；只在第一次真正需要提醒（或把开关重新打开，属用户手势）时请求权限，拒绝后不再弹。Windows toast 仍受 AppUserModelID/快捷方式限制（PLAN 第 6 节），所以“系统通知”不作为验收必过项，页内条才是兜底。
- **T15 开关与存储**：`localStorage` 的 `study.notify.completion.enabled`（缺省=开，`'0'`=关）；存储被禁（隐私模式、沙箱 iframe）时降级为内存区域，提醒仍工作但重启后不保留。关掉会立即清空待发窗口与已显示的条目。
- **T15 跨所有权改动**：新增 `client/messages/notify.js`——`tests/client/copy.test.mjs` 禁止 `client/messages/` 之外出现中文，文案只能进字典；并在 `client/plugin.js` 里加 1 行 import 与 1 行 `installCompletionNotify(ctx, { namespace: NS })`——barrel 只自动发现 `pages/messages/actions`，非页面模块没有其它注册点。`client/plugin.js` 的 `inject` 仍是 `['slots','locale']`（T02 断言不变），`sessions` 用 `ctx.inject(['sessions'], …)` 就地等待，客户端没有会话服务时提醒整体不出现。
- **T15 的验收边界**：`tests/notify/ui-smoke.mjs` 只证明两个真实外壳接点——`settings.general.item` 的设置行渲染、开关写入与刷新保持，以及 `shell.overlay` 的提示条在无完成时安静挂载（它先前的 `selector is not a function` 崩溃已由该脚本暴露并修复）。提示条的文案/合并/降级由 47 个单元测试覆盖；真实“跑一轮对话再看到提示条”需要模型或 T19 全场景回归，本任务没有驱动。
- **T15 共享产物与并行任务**：`client/client.js`、`client/.build/entry.js` 是全体客户端任务共用的构建产物，谁最后构建谁覆盖；本次构建同时打包了 T05 的 `workbench` 页（T15 未修改其文件），并顺带修好了 T05/T09 记录过的 `notify/notifier.test.mjs` react 解析失败与产物新鲜度失败。
- **T03 路线 1（零补丁宽右栏）**：真实 DSH Web 0.2.2-rc.1 + Edge，1440×900。`sidebarRightTabs` + `sidebar.right.pane.tab` 能在空白“新会话”下、发送第一条消息前打开学习区；右栏上限由 `min(70%×帧宽, 帧宽−左栏−400)` 决定，导航展开 280px 时 **760px**、收成 56px 轨道时 **984px**，对话列始终 400px；刷新恢复 session/面板/标签。但学习区固定在**右**栏、对话在左，方向与 T04 目标相反；打开“插件”等全局面板替换对话时右栏与学习区一起消失；界面没有真正的“无 session”状态可测。因此路线 1 只保留为回退/窄窗口入口。
