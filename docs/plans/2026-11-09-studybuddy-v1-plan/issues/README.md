## 复现与验证范围

[复现脚本](evidence/design-code-review-probes.mjs)使用现有测试辅助代码和临时 SQLite 数据库，输出 11 个场景的实际返回值，退出时清理临时数据库。脚本用于观察问题，不以进程退出码判断问题已修复；修复后应将相应场景改写为有明确断言的回归测试。

在仓库根目录、已配置项目运行依赖与兼容 Node 的环境下运行：

```powershell
node docs/plans/2026-11-09-studybuddy-v1-plan/issues/evidence/design-code-review-probes.mjs
```

审查时已执行的测试、失败原因及复跑结果见[报告验证记录](2026-11-10-design-code-review.md)。整理文档时不重新宣称这些历史测试通过，也不把报告当作修复验收结果。

## 建议修复顺序

1. 统一任务、时间块和进度，再修复身份、并发、剩余量计算、目标作用域与幂等。
2. 完成受限个人插件宿主的技术验证，补齐默认权限边界。
3. 接通后台复盘、学习通知、恢复补跑、拆分与暂定安排，再完善记忆提取及纠错。
4. 补资料证据、换书、对话建档、滚动细化、同日拖拽与成果展示。
5. 完成独立安装包、升级备份和匹配版本回滚，按设计场景验收。
