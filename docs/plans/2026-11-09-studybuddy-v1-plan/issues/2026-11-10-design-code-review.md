# StudyBuddy 设计与代码对照审查

审查日期：2026-11-10。本文记录该次审查结果，不表示问题已经修复。问题导航见 [README](README.md)。

审查依据仅为指定[设计文档](../../../specs/2026-11-08-studybuddy-redesign-design.md) 与当前项目代码（包括测试代码）。没有采用实施计划、进度说明、历史验收截图或外部资料作为完成依据。未修改项目源代码；复现使用临时数据库。

当前已具备 SQLite 业务服务、资料文字/PDF 导入与中文检索、计划草案/正式修订/撤销、任务与时间块直接操作、五种进度、确定性番茄钟与中断恢复、任务答疑上下文、提醒面板、记忆增删改查、日周月成果和基础导出/冷备份。主要问题是这些能力尚未形成设计要求的统一闭环。

以下 22 项按修复影响排序。P0 表示默认发行前必须解决的明确权限边界缺口；P1 表示会破坏业务事实或核心使用过程；P2 表示设计中的功能缺口或体验不完整。“复现”表示执行了真实模块服务调用；“静态确认”表示由调用链或数据结构直接确认，未声称完成桌面实测。

<a id="issue-01"></a>

**01 · P1 · 计划条目与工作台任务是两套业务事实（复现）**

- 设计：§4.3、§5、§6，界面和 Agent 使用同一份任务、进度和安排。
- 代码：[plans.mjs:1615](../../../../plugins/study/host/modules/plans.mjs#L1615) 只保存计划 JSON 修订；[tasks.mjs:1039](../../../../plugins/study/host/modules/tasks.mjs#L1039) 读取独立的任务/时间块表；[tutoring.mjs:527](../../../../plugins/study/host/modules/tutoring.mjs#L527) 通过标题寻找计划关联。
- 结果：确认含 1 项任务的计划后，工作台任务数和时间块数均为 0。计划条目也无法直接用于只接受 `study_task` ID 的计时、提醒与任务答疑。反向拖拽工作台时间块不会更新计划修订。
- 建议：让计划版本引用稳定 `taskId` 和独立 `blockId`，统一进度账本；确认、手动拖拽和 Agent 调整都写入同一事务服务。迁移现有数据时保留旧 ID 与记录关联，不能用标题作为身份。

<a id="issue-02"></a>

**02 · P0 · 默认个人插件没有设计要求的隔离执行环境（静态确认）**

- 设计：§9，默认生成工具必须无 Node、无任意文件/网络能力，经过隔离预览和受控桥接，用户再启用。
- 代码：[project-config.mjs:16](../../../../scripts/project-config.mjs#L16) 启用上游原生 Creator；[creation-recommendations/src/index.ts:273](../../../../source/deepseek-harness/packages/experimental/creation-recommendations/src/index.ts#L273) 创建原生 DSH 包；[生成规则 data.md](../../../../plugins/study/creator/skills/study-creator/references/data.md) 允许 Host 插件，并明确安装页面没有沙箱。
- 缺口：当前约束来自提示词，插件实际可运行进程内代码。未见默认受限插件宿主、按能力授权的学习桥接或插件独立记录服务。固定 namespace 注册表也没有提供受控的插件记录入口。
- 建议：先实现最小隔离宿主与能力白名单，使用独立插件 ID 隔离记录；学习数据读写必须经校验桥接。原生插件另设高级入口，展示本机代码权限。默认流程补齐“隔离预览 → 用户启用”，保留现有停用/恢复能力。

<a id="issue-03"></a>

**03 · P1 · 旧草案能覆盖较新的手动草案（复现）**

- 设计：§4.6、§6、§8，前台操作优先，过期结果不能覆盖新修改。
- 代码：[plans.mjs:1498](../../../../plugins/study/host/modules/plans.mjs#L1498) 只校验正式 `baseRevision`；修改草案不提升正式版本，也没有比较草案自己的修订号。
- 结果：正式版本同为 1 时，先保存新手动草案，再提交旧 Agent 草案，后者被接受并覆盖前者。
- 建议：草案增加独立递增版本，所有草案写入携带 `expectedDraftRevision`；冲突时返回最新草案和差异。由适配层强制携带版本，不能只把它列为可选参数。

<a id="issue-04"></a>

**04 · P1 · 任务 ID 会随改期改变，完成记录脱离当前任务（复现）**

- 设计：§6，ID 不随拖拽、跨天重排、更换展示方式改变。
- 代码：[plans.mjs:622](../../../../plugins/study/host/modules/plans.mjs#L622) 的可选 ID 默认由标题、材料、预计时间、日期、起止时间等内容生成。
- 结果：已完成条目改到明天，修订时省略允许省略的 ID，新条目得到新 ID，当前进度变成 `unrecorded`。旧记录仍在数据库，但失去当前条目关联。
- 建议：首次创建分配不可变 ID，后续使用显式操作 `move/update/split/replace`；修改已有条目必须带 ID。拆分执行块保留任务身份。

<a id="issue-05"></a>

**05 · P1 · 连续复盘重复折算部分完成量（复现）**

- 设计：§4.6，重排只能处理真实剩余工作。
- 代码：[followup.mjs:1180](../../../../plugins/study/host/modules/followup.mjs#L1180) 用当前估算乘剩余比例；[followup.mjs:1241](../../../../plugins/study/host/modules/followup.mjs#L1241) 又把折算值写回任务估算。
- 结果：60 分钟、完成 5/10 的任务第一次复盘剩余 30 分钟；没有任何新进度，第二天复盘却只剩 15 分钟。
- 建议：保留原始估算、总工作量和累计完成量；单独计算剩余工作或执行块预算。复盘不覆盖计算基数，同一份进度重复计算应得到相同剩余量。

<a id="issue-06"></a>

**06 · P1 · 切换备考目标不能切换对应业务上下文（复现）**

- 设计：§7.4，多个目标，默认只激活一个，材料问题与观察按目标关联。
- 代码：[plans.mjs:988](../../../../plugins/study/host/modules/plans.mjs#L988) 按全局更新时间选择计划；[tasks.mjs:1039](../../../../plugins/study/host/modules/tasks.mjs#L1039) 返回所有活跃任务；任务表没有 `goal_id`。复盘状态查询也只有日期，没有目标维度。
- 结果：创建 A/B 两个目标及计划，再激活 A，默认读取仍返回最近创建的 B 计划。
- 建议：统一解析当前 `goalId`，任务、计划、材料检索、复盘、统计和会话上下文都按该作用域读取；复盘去重键包含 `goalId + date`。允许显式查看历史目标。

<a id="issue-07"></a>

**07 · P1 · 进度询问在开始时间触发，且按半天合并身份（复现）**

- 设计：§4.5，预计结束仍未勾选时询问，每个计划执行时段主动问一次。
- 代码：[followup.mjs:570](../../../../plugins/study/host/modules/followup.mjs#L570) 比较 `first.startMinute`，提醒键为 `task + date + morning/afternoon/...`。
- 结果：09:00–10:00 的任务在 09:00 已进入“到点询问”。同一任务在同一上午的两次执行也只能产生一个询问身份。
- 建议：以执行块的预计结束时间和块 ID 建立提醒身份；多项到期只合并展示，不合并各块的处理状态。重新检查最新进度后再发送。

<a id="issue-08"></a>

**08 · P1 · 晚间自动复盘、恢复补做和学习系统通知尚未接通（静态确认）**

- 设计：§4.6、§8，默认授权日常微调，复用 Schedule，后台运行可跟进，恢复仅补最近仍有意义事项。
- 代码：[followup.mjs:168](../../../../plugins/study/host/modules/followup.mjs#L168) 只启动存活心跳；[reminders.js:331](../../../../plugins/study/client/pages/reminders.js#L331) 自动加载预览，而 [reminders.js:380](../../../../plugins/study/client/pages/reminders.js#L380) 只在用户点击后保存。当前学习提醒依赖 Renderer 轮询和应用内横幅；[notify.js:1](../../../../plugins/study/client/notify.js#L1) 的系统通知针对模型回复结束。番茄结束未接学习通知。
- 缺口：没有 StudyBuddy Schedule 注册、默认自动调整开关/执行链、最近有效复盘补跑，也没有学习提醒与系统通知共享身份的桥接。直接放弃恢复前提醒可能漏掉当天仍有意义的询问。
- 建议：由本地状态决定是否运行，Schedule 触发确定性业务服务；按目标和日期持久化状态与失败重试。桌面通知读取同一提醒账本，Renderer 不承担后台调度。恢复只合并最近有效事项，保存成功后显示调整摘要。

<a id="issue-09"></a>

**09 · P1 · 重排不支持拆分、待确认的暂定安排和未安排工作的再次调度（部分复现）**

- 设计：§4.6，拆分后续执行块，待确认工作可暂定安排，确认完成后清理重复块，总量不足时保留待安排工作。
- 代码：[followup.mjs:985](../../../../plugins/study/host/modules/followup.mjs#L985) 跳过 `date === null`、未记录和待确认条目；[followup.mjs:1220](../../../../plugins/study/host/modules/followup.mjs#L1220) 只尝试整项放入某一天。
- 结果：未来两天各有 30 分钟，一个 60 分钟任务仍全部未安排。已变成 `date: null` 的剩余任务不会进入下次重排；待确认工作留在过去，没有暂定执行块或完成后的清理流程。
- 建议：任务与执行块分离后，按剩余量拆块，先用预留空间、再移动弹性块。待确认块携带假设与来源进度版本；确认后清理暂定重复块。未安排队列必须参与后续重排，并解释阶段目标影响。

<a id="issue-10"></a>

**10 · P1 · 普通对话的批量记忆提取未实现（静态确认）**

- 设计：§7.3，晚间/压缩后批量处理新增证据，共享消息位置，避免重复调用，允许取消且费用可见。
- 代码：[memory.mjs:67](../../../../plugins/study/host/modules/memory.mjs#L67) 只有显式 remember/recall/forget 和上下文注入；未接复盘、压缩事件、历史消息游标或后台提取任务。
- 建议：增加轻量提取协调器，复用当前模型和既有会话历史；按会话保存处理游标，晚间/压缩共享游标，只处理新增用户证据。保存提取费用、失败状态与取消入口；无需第二把 Key 或向量服务。

<a id="issue-11"></a>

**11 · P1 · 记忆没有目标/会话作用域，自动注入也不按相关性检索（静态确认）**

- 设计：§7.2–§7.4，学生偏好、目标观察、临时会话上下文分层，保留原话来源，按相关性加载少量内容。
- 代码：[memory.mjs:54](../../../../plugins/study/host/modules/memory.mjs#L54) 不接受 `goalId/sessionId/messageId`；[memory.mjs:164](../../../../plugins/study/host/modules/memory.mjs#L164) 来源只有 actor/requestId/时间/可选自由文本；[memory.mjs:330](../../../../plugins/study/host/modules/memory.mjs#L330) 按类型和更新时间固定选 8 条。
- 影响：目标之间混用状态；无法可靠返回原话核验；偏好多时会挤掉相关状态和观察。
- 建议：保存结构化作用域和对话证据引用；自动注入按当前目标、任务与用户问题检索，并控制总字符/Token 预算。明确用户陈述与 Agent 待确认观察。

<a id="issue-12"></a>

**12 · P1 · 纠正后旧记忆能重建，删除抑制只覆盖有限的正文哈希（复现+静态确认）**

- 设计：§7.2，新的纠正替代旧结论，删除后不被旧对话立即重建。
- 代码：[memory.mjs:164](../../../../plugins/study/host/modules/memory.mjs#L164) 修改原记录不保留被替代关系；[memory.mjs:246](../../../../plugins/study/host/modules/memory.mjs#L246) 墓碑按规范化正文哈希匹配，超过 500 条时删除旧墓碑。
- 结果：把“上午学数学”改为“晚上学数学”，再写入旧句，旧句正常创建，两个相反偏好同时存在。近义改写也不会匹配正文哈希。
- 建议：保存修订/替代关系和证据范围；提取前检查旧证据是否已纠正或删除，明确偏好冲突时优先最新用户纠正。墓碑生命周期应与旧证据的可重提取范围一致。

<a id="issue-13"></a>

**13 · P1 · 幂等身份仍为可选，部分 Agent 工具没有传递（复现）**

- 设计：§6，重复点击、模型重试、调度补跑不能重复写入。
- 代码：[kernel.mjs:110](../../../../plugins/study/host/kernel.mjs#L110) 允许缺少 requestId/expectedRevision；[memory.mjs:110](../../../../plugins/study/host/modules/memory.mjs#L110) 工具写入只传 actor，资料导入也没有稳定操作身份。
- 结果：相同记忆以 Agent 身份连续写入两次，得到两条相同记录。已有“同 requestId 不重复”测试只覆盖调用方确实传 ID 的路径。
- 建议：UI、工具、Schedule 适配层强制生成并持久化逻辑操作 ID；同一次重试复用该 ID。工具调用 ID 可用于执行器重试，跨模型调用的逻辑重试还需业务去重。追加进度和资料导入同样覆盖。

<a id="issue-14"></a>

**14 · P1 · 期限与实际工作量尚未进入完整容量判断（期限问题已复现）**

- 设计：§4.2，综合期限、固定事项、先后关系、学习/练习/订正/休息，之后用实际记录修正估算。
- 代码：[plans.mjs:786](../../../../plugins/study/host/modules/plans.mjs#L786) 读取 deadline 但不判断条目日期是否超过期限；容量按 JSON 内估算汇总，不合并工作台固定块，未使用计时记录校准估算。
- 结果：考试期限为 11 月 10 日的目标，11 月 12 日任务仍判定 `fits`，无风险且可直接正式确认。
- 建议：统一日历后合并固定约束、有效日期、依赖和完整工作预算；超期产生明确风险与阶段影响。保留用户试行决定，不能静默把超期安排判为可行。实际时长用于提出估算修订，保留原始证据与用户决定。

<a id="issue-15"></a>

**15 · P2 · 公开备考资料缺少来源链接和适用年份的可靠入库流程（静态确认）**

- 设计：§4.1，保存来源、查询日期和适用年份，年份不明不得作为当年确定要求。
- 代码：[materials.mjs:827](../../../../plugins/study/host/modules/materials.mjs#L827) 支持本地/粘贴内容；[materials.mjs:904](../../../../plugins/study/host/modules/materials.mjs#L904) 粘贴入库固定 `sourceRef: null`；[materials.mjs:1378](../../../../plugins/study/host/modules/materials.mjs#L1378) 后续更新也不能补来源。资料表没有适用年份、公开信息核验类型。
- 建议：增加公开来源导入/引用入口，记录原 URL、抓取/查询日期、适用年份、读取与核实状态。保留 DSH 搜索能力，但将检索结果的证据写入业务资料服务；不明年份必须显式标记。

<a id="issue-16"></a>

**16 · P2 · 计划页码/题号可直接被当作已核实信息（静态确认）**

- 设计：§4.1、§5，材料位置不足要标记粗略任务，不能凭空补页码题号，统一服务负责事实校验。
- 代码：[plans.mjs:491](../../../../plugins/study/host/modules/plans.mjs#L491) 只做字段类型校验；填了 page/chapter/exercise 就不能同时标记为 unverified，没有检查对应材料证据，模型可以提交无出处位置。
- 建议：位置数据带原文片段/目录条目/学生声明等证据引用；无法验证时保存“待核实位置”和假设，允许粗略任务执行。不要让非空字段自动意味着已核实。

<a id="issue-17"></a>

**17 · P2 · 更换教材没有明确替代关系（静态确认）**

- 设计：§6，保留原书完成记录，新任务建立明确替代关联，不能迁移未被证实的完成量。
- 代码：[tasks.mjs:89](../../../../plugins/study/host/modules/tasks.mjs#L89)、[plans.mjs:111](../../../../plugins/study/host/modules/plans.mjs#L111) 没有 replaces/supersedes 等关联字段或替换操作；直接改材料仍可能沿用同一条目的完成状态。
- 建议：新增明确 `replaceMaterial/replaceTask` 操作，新建任务并引用旧任务；原书完成量保持原属。只有用户确认有依据的映射时才关联等价工作。

<a id="issue-18"></a>

**18 · P2 · 自然对话建档、默认备考会话和滚动细化缺少产品接入（静态确认）**

- 设计：§4.1、§4.2、§4.4，对话逐步了解目标，默认持续备考对话，远期目标/近期任务滚动细化。
- 代码：[onboarding.js:28](../../../../plugins/study/client/pages/onboarding.js#L28) 是目标→材料→草案→确认表单；[materials.mjs:135](../../../../plugins/study/host/modules/materials.mjs#L135) 的模型工具只支持检索、文字导入、列表，没有目标读写；发行配置未注册学习规划/陪伴 preset 或默认备考会话映射。
- 缺口：现有计划工具可人工/对话提交草案，但没有持久的“目标→备考主会话”关联、按日启动细化、按实际执行校准近期工作量的触发流程。
- 建议：保留表单为快捷补充入口，增加目标服务工具和简短学习上下文；按目标保存主会话 ID，任务答疑继续可另开。实现可配置的滚动细化窗口，不把建议的 7 天做成不可调整要求。

<a id="issue-19"></a>

**19 · P2 · 拖拽只改日期，不能在一天内改时段（静态确认）**

- 设计：§4.3，直接拖拽时间安排，默认只移动所选块并立即提示冲突。
- 代码：[workbench.js:440](../../../../plugins/study/client/pages/workbench.js#L440) 接受的拖放目标只有日期，同一天直接 return；提交 payload 也只有 date，保留原起止时间。
- 建议：支持拖到日历中的起始分钟，提交日期、开始、结束及版本；同日移动、跨日移动、时段冲突使用统一校验。目前手动编辑时刻可用，但没有完整的拖拽排时体验。

<a id="issue-20"></a>
