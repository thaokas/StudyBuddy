# 已接受的范围裁剪

本文件记录“原设计有要求，但精简版 v1 不做”的事项。它们不是当前修复任务；新会话不要因为机械对照原设计而擅自扩大范围。若用户改变决定，应新建任务卡并更新 `PLAN.md`。

## 1. Creator 隔离沙箱（issue 02）

- 决策：直接用 DSH 创造模式；个人工具的开发环境不再实现“不依赖 Node”的隔离宿主。
- 依据：`session-116db5ef` 的 1.2；`tasks/T16-creator-modes.md` 的“不做：自建隔离沙箱、权限限制承诺、代码审计工具”。
- 当前正确说法：生成插件和 Creator 有相同本机权限，**不是沙箱**；只承诺可移除、可停用/恢复。
- 仍需做（不写代码）：`docs/creator.md`、`plugins/study/creator/README.md` 和界面文案保持一致，不能宣称“受限/安全小工具”。
- 如果将来要对外宣传安全沙箱，必须另开任务，先验证隔离宿主、能力白名单和独立记录命名空间。

## 2. 普通对话自动批量记忆提取（issue 10）

- 决策：v1 不做，留到 v1.1。
- 依据：`tasks/T20-memory.md` 的“不做：向量检索、图数据库、自动批量提取（v1.1）”。
- 本轮只要求：显式 `remember/recall/forget`、跨会话注入、删除抑制、纠错抑制（SB-14）。
- 不要把“普通聊天不会自动写入记忆”当作本轮回归失败。

## 3. 安装器、签名、自动更新、匹配版本回滚（issue 21 的大部分）

- 决策：T18 只交付候选 ZIP、启动脚本、版本清单和运行说明，不承诺安装器。
- 依据：`tasks/T18-release-candidate.md` 的“不做：安装器、签名、自动更新、对外发布”；`tasks/T17-backup-export.md` 的“不做：热备份、自动更新、云同步”。
- 本轮要做：SB-17 的候选包、版本锁定、干净目录启动、不连接上游更新源、许可/来源、冷备份说明。
- 不做：NSIS/MSI 安装器、代码签名、自动更新通道、升级失败后恢复匹配应用版本。原设计场景 14 可在 T19 记为“未覆盖+原因”。

## 4. 公开院校信息联网入库（issue 15）

- 决策：T08 明确“不做联网检索院校信息”。
- 本轮只要求本地/粘贴资料和现有来源字段；公开 URL、查询日期、适用年份留到后续。
- 如果后续接 DSH 搜索，再新增卡片，把证据写入材料服务，年份不明必须显式标记。

## 5. 原始会话/导入文件导出（issue 22 的一部分）

- 决策：T17 只要求业务记录、记忆和成果导出，排除凭据；原始会话/导入文件是原设计的“可选”内容。
- 本轮要做：修复成果可用性判断、提供应用内导出入口（SB-13）。
- 不做：把会话日志 zstd、附件原件打包进 JSON 导出；完整冷备份仍按 T17。

## 6. 跨日补发历史提醒（issue 08 的一部分）

- 决策：T12 明确“关闭应用不补发历史提醒”；开机不逐条补发是预期行为。
- 本轮要做：同一天内仍有效的复盘/提醒、启动摘要和失败状态；不做跨日逐条补发。
- 恢复后只允许合并最近仍有意义的复盘，不重放几天前的卡片。

## 7. 个人工具版本历史/修改已有工具（issue 02 的附带项）

- 决策：本轮只验证 DSH Creator 的生成、安装、重启、撤销、恢复；不支持在卡片里修改已有插件，也没有多版本历史。
- 这是 DSH Creator 的现状，不作为本轮代码缺陷；如果用户要“修改/多版本”，另开任务。

## 8. 触屏拖拽、跨平台凭据、多账号隔离

- 本轮首发 Windows、鼠标拖拽；触屏未验证不作为失败。
- 凭据仍用 Windows DPAPI；macOS/Linux 适配后置。
- 一个 OS 用户一个本地学生档案；不做多账号同机隔离。
