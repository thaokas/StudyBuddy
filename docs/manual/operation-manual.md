## 1. 快速开始

第一次使用按下面五步走即可。

| 步骤 | 做什么 | 去哪里 |
| --- | --- | --- |
| 1 | 启动应用 | 双击 `start-studybuddy.cmd`，或在项目根目录执行 `.\start-studybuddy.cmd` |
| 2 | 配置模型 | 设置 → 模型；预置提供商 `StudyBuddy DeepSeek`，填入 API Key |
| 3 | 创建计划 | 左侧栏「创建计划」→ 目标 → 材料 → 计划需求 →「让助手开始规划」 |
| 4 | 安排今天 | 「工作台」→ 今日 → 给任务添加时间块 |
| 5 | 开始学习 | 「番茄钟」计时；到点后在「提醒」里答复完成情况 |

**我想…… → 去哪里**

| 需求 | 入口 |
| --- | --- |
| 让助手帮我规划一整门课 | 创建计划 |
| 看今天/本周要做什么、几点做 | 工作台 |
| 专注计时 | 番茄钟 |
| 安排今天几点学什么 | 工作台 → 今日 → 添加时间块 |
| 记录“做完了/做了一半” | 工作台任务行「记录进度」，或计划页条目进度 |
| 看这周完成了多少 | 成果 |
| 看我问过哪些题、哪些还没弄懂 | 问答记录 |
| 让助手记住我的偏好 | 记忆，或直接在对话里说「记住……」 |
| 让助手晚上帮我顺延没做完的任务 | 提醒 → 晚间复盘 |
| 换一台机器继续用 | 备份与恢复 |
| 把学习数据导出成 JSON | 设置 → 通用设置 →「导出学习数据」，或在对话里说「导出学习数据」 |

> **开始前请先看第 2.3 节「当前版本边界」**：v1 是开发版，没有安装包、没有云同步，部分功能有明确限制。这些限制不是故障。

## 2. 项目概览

### 2.1 这是什么

StudyBuddy 是一个**本地优先**的学习助手：桌面外壳来自 DeepSeek Harness（DSH）源码，学习能力由项目自带的 `plugins/study-*` 插件组提供。它把“备考目标 → 计划 → 每天几点做 → 完成记录 → 阶段成果”串成一条闭环，并在这个闭环上叠加了问答记录、学习记忆、讲解画像和规则版学习分析。

几个关键事实：

- **数据在本机**。学习数据存放在 `.studybuddy/study/study.db`（SQLite），记忆也在同一个数据库里；没有云同步、没有账号体系。
- **模型只负责语言与规划**。提醒、计时、成果统计、周报、画像推断都由本地规则完成，不调用模型；断网时这些功能仍然可用。
- **模型 Key 由 Windows DPAPI 加密**，存放在 `.studybuddy/home/credentials.dpapi`，只能由创建它的 Windows 用户解密。
- **界面是 DSH 原生界面**。模型设置、插件页、会话列表、Agent 预设都沿用 DSH；学习页以左侧栏页面入口的形式接入。

### 2.2 能力一览

| 能力 | 说明 | 是否依赖模型 |
| --- | --- | --- |
| 创建计划 | 目标、材料、计划需求三步；可让助手在对话里规划，也可手写草案 | 助手路径需要；手动路径不需要 |
| 计划管理 | 项目、任务日期、修订、撤销、容量与缺失信息 | 否 |
| 工作台 | 今日/本周任务与时间块、拖拽、重叠确认、进度、完成率 | 否 |
| 番茄钟 | 学习/休息计时、关联任务、暂停/继续/结束、重启恢复 | 否 |
| 提醒 | 到点提醒、快捷答复、静默时段、专注延后、稍后提醒 | 否 |
| 晚间复盘 | 预览未完成弹性任务的顺延方案，手动确认后保存 | 否 |
| 成果 | 日/周/月三种口径、取消单独统计、材料推进、按天明细 | 否 |
| 问答记录 | 自动捕获学生提问，切分问答单元、规则摘要、合并/拆分 | 否 |
| 记忆 | 偏好、短期状态、待确认观察；删除后不会被旧对话重建 | 否 |
| 画像 | 六项讲解参数，按证据自动微调，也可手动调整 | 否 |
| 学习分析 | 弱主题、方法信号、周/月规则版报告 | 否 |
| 创造模式 | 让 Agent 生成并安装可长期使用的页面/小工具 | 是 |
| 备份/恢复/导出 | 冷备份、校验、恢复、JSON 导出 | 否 |

### 2.3 当前版本边界

以下限制来自当前源码与验收记录，属于**已知设计边界**，不是待修复的偶发问题：

| 边界 | 具体表现 |
| --- | --- |
| 开发版 | 没有安装包；必须从源码目录启动，依赖已构建的 `source/deepseek-harness` |
| Windows 限定 | 凭据使用 Windows DPAPI `CurrentUser`；非 Windows 平台不能直接使用此配置 |
| 无云同步、无自动更新 | 数据只在本机；升级需要手动处理源码与补丁 |
| 无数据库迁移器 | 备份必须用创建它的同一版本恢复；schema 不兼容时插件会拒绝启动 |
| 提醒只在运行时生效 | 关闭应用期间错过的提醒不补发；重启后也不会重新弹旧提醒 |
| 无独立项目 CRUD | 项目随计划草案/修订维护；界面不提供单独的新建/删除项目页 |
| 无目标切换栏 | 页面顶部不再有“当前目标”选择器；需要新目标时在创建计划页新建 |
| 计划只分配日期 | 具体几点做要到工作台排时间块；拖时间块到另一天不会改写计划分配日期 |
| 纯附件消息不捕获 | 问答记录只捕获带文字的提问；只发图片/文件、没有文字的消息不入库 |
| 英文界面部分中文 | 服务端生成的摘要、里程碑、错误信息目前仍是中文 |
| 拖拽只覆盖鼠标 | 触屏拖拽未验证/未实现 |
| 生成插件不是沙箱 | 创造模式安装的插件与普通插件同权限；只承诺“可撤销、可移除” |
| 导出不是备份 | JSON 导出是只读快照，不是可恢复镜像；完整恢复用冷备份（6.6 / 6.7） |

> **当前进度**：8 个 study 插件已落地（插件拆分 P0 契约冻结、P1–P6 实现已落地），P7 bundle 与 T18/T19 验收仍未完成，不要把它当成已发布的安装包。状态与证据入口见 [`docs/roadmap.md`](../roadmap.md)，架构与契约见 [`docs/architecture.md`](../architecture.md)、[`docs/contracts.md`](../contracts.md)。

### 3.1 前置条件

| 项目 | 要求 | 本机实测 |

检查命令：

```powershell
node --version
pnpm --version
Test-Path .\source\deepseek-harness\apps\desktop\.desktop-build
```

三项都正常后再启动。若最后一项是 `False`，先按 3.3 节重建。

### 3.3 首次安装或从零重建

新机器、源码被删、或依赖损坏时执行。耗时参考：安装约 3.5 分钟，首次构建约 2.5 分钟。完整步骤（含 patch 说明、测试与新增插件）见 [`docs/development.md`](../development.md)；下面是可照做的最小流程，命令都在项目根目录执行。

```powershell
git clone --no-checkout https://github.com/deepseek-ai/deepseek-harness.git source/deepseek-harness
git -C source/deepseek-harness checkout fcc0ad462172522aaf5c93a7b2e01f6b9f0b0159
$p1 = (Resolve-Path patches/0001-desktop-account-toggle.patch).Path
$p2 = (Resolve-Path patches/0002-second-main-column.patch).Path
$p3 = (Resolve-Path patches/0003-desktop-tray-icon.patch).Path
git -C source/deepseek-harness apply "$p1" "$p2" "$p3"
cd source/deepseek-harness
pnpm install --frozen-lockfile --reporter append-only
$env:DSH_GATE_CONCURRENCY='2'; $env:DSH_GATE_FAIL_FAST='1'
pnpm run build
pnpm --filter @deepseek-ai/dsh-desktop exec install-electron
cd ..
```

然后回到项目根目录，按第 4 节启动。

> 三枚补丁必须按序应用，patch 路径要写成 `Resolve-Path` 解析后的绝对路径：`git -C` 会把 Git 的工作目录切到源码树，相对路径会解析到错误位置。应用或修改补丁后必须重新 `pnpm run build`，否则产物不含补丁改动。补丁内容与反向校验见 [`patches/README.md`](../../patches/README.md)，升级时重放补丁见 19.3 节。

### 3.4 版本关系

| 组件 | 版本/基线 | 说明 |
| --- | --- | --- |
| DeepSeek Harness | 0.2.2-rc.1，基线提交 `fcc0ad4` | 源码固定在 `source/deepseek-harness`，已应用 `patches/0001`–`0003`（未提交） |
| Study 插件组 | 8 个包均为 0.1.0 | 旧 `plugins/study` shell 已删除；数据根由启动器传入 `<数据根>/study` |

| 学习数据 schema | 核心 v1；模块各自 `schemaVersion: 1` | v1 无迁移器 |

## 4. 启动、退出与重启

### 4.1 日常启动

在项目根目录执行：

```powershell
.\start-studybuddy.cmd
```

推荐 `.cmd` 而不是 `.ps1`：本机 PowerShell 执行策略限制未签名脚本，`.cmd` 不需要修改策略。

脚本使用 PATH 中的 `node`（要求 ≥ 24.9）。启动后终端会一直被占用，这是正常的——关闭窗口或按 `Ctrl+C` 才会退出。

### 4.2 启动脚本做了什么

每次启动 `scripts/start-studybuddy.mjs` 会：

1. 确定数据根（默认 `.studybuddy`，可用 `STUDYBUDDY_DATA_DIR` 覆盖）。
2. 拒绝在 `source/deepseek-harness/.env` 存在时启动，避免旧凭据文件与新凭据服务混用。
3. `prepareProfile()`：
   - 创建/保留 `home/profiles/desktop/`；
   - 确保 profile 加载 `@deepseek-ai/dsh-base`、`@deepseek-ai/dsh-web-app`、`@deepseek-ai/dsh-personalized-recommendations` 三个 bundle（已被你在插件页关掉的 Creator bundle 不会被强行加回）；
   - 写入 8 个插件行（core → facts → learning → reminders → memory → outcomes，外加 appearance、pet）与 DPAPI 凭据行，只有 core 接收 `dataDir`；
   - 把 `skills/study-creator` 复制到 `<数据根>/home/skills/`；
   - 首次创建模型默认值（自定义提供商 `studybuddy-deepseek` / 模型 `deepseek-flash` / High 档）。
4. 首次初始化时尝试导入一次 API Key（来源见 5.5），之后不再自动导入。
5. 清理继承的 `DSH_*` / `ELECTRON_*` 环境变量，设置隔离的 `DSH_HOME`、`DSH_AGENTS_HOME`、`DSH_DESKTOP_USER_DATA_DIR`，关闭账号与遥测。
6. 自动选择三个空闲调试端口，写入 `<数据根>/launch.json`。
7. 启动 `pnpm run start:desktop`，等待 Electron 窗口出现。

首次启动（或删过 `.desktop-build`）会先准备独立运行时，可能需要几分钟；之后是秒级启动。

### 4.3 使用独立数据目录

不想影响当前学习数据时，指定另一个数据根：

```powershell
$env:STUDYBUDDY_DATA_DIR = 'D:\StudyBuddyData'
.\start-studybuddy.cmd
```

该目录会拥有自己的 `home/`、`study/`、`workspace/`、`agents/`。注意：

- 换数据根等于换一整套数据与凭据；新根首次启动会重新走初始化。
- `STUDYBUDDY_DATA_DIR` 只影响本项目启动器，不影响 DSH 的其它启动方式。
- 备份脚本用同一个变量或 `--data-dir` 指定数据根。

### 4.4 只初始化、不启动

```powershell
node scripts/start-studybuddy.mjs --prepare-only
```

它只写 profile、模型默认值、Creator skill 与凭据初始化，然后退出；不会启动应用，也不会请求模型。适合排查“启动前的配置是否正确”。

### 4.5 退出与残留进程

正常退出：关闭 StudyBuddy 窗口，等终端里的启动器退出；若终端仍挂着，按 `Ctrl+C`。

窗口关了但进程残留时：

```powershell
Get-Process electron -ErrorAction SilentlyContinue
taskkill /IM electron.exe /F
```

> 强制结束前尽量确认没有正在保存的写操作。备份脚本也会检查应用是否仍在运行，运行中会拒绝备份。

### 4.6 修改代码后的重启

| 改动位置 | 需要做什么 |
| --- | --- |
| `plugins/<插件>/client/**` | `node plugins/<插件>/scripts/build-client.mjs`，然后重启应用 |
| `plugins/<插件>/host/**` | 重启应用（宿主模块在启动时加载） |
| `scripts/**`、`platform/**` | 重启应用 |
| `source/deepseek-harness/**` | 重新构建源码，见 19.1 |
| 只改模型/Key | 不需要重启；在设置里保存后新请求生效 |

客户端 bundle 有“产物新鲜度”测试：改了某个插件的 `client/**` 却没重新构建，该插件 `tests/client/` 下的构建/复制测试会失败。

### 4.7 启动失败先看哪里

1. 终端最后 30 行报错。
2. `.studybuddy/logs/desktop-launch.log`（如果本次启动写入了日志）。
3. `.studybuddy/launch.json` 是否存在、端口是否被占用。
4. 用 `--prepare-only` 单独验证配置阶段。
5. 仍无法定位时按 20 节“启动与进程”逐条排查。

### 4.8 首次启动的欢迎页

- 首次打开会先显示预览版说明，关闭后进入欢迎页。
- 「添加 API Key」：填入模型密钥后即可开始对话；Key 走 DPAPI 加密保存，见 5.5。
- 「稍后配置」：以无 Key 状态进入工作区，可以先看界面、建手动计划、用工作台/番茄钟；聊天需要 Key 时再补。
- 没有账号登录/订阅引导；之后要改 Key，随时去「设置 → 模型」。

## 5. 模型与凭据

### 5.1 打开模型设置

应用窗口 → **设置 → 模型**。这是 DSH 原生设置页，新增、编辑、删除提供商/模型/API Key 都在这里完成；本项目没有另做一套模型界面。

### 5.2 预置的提供商与模型

首次初始化会写入：

| 项 | 值 |
| --- | --- |
| 提供商 id | `studybuddy-deepseek` |
| 显示名称 | `StudyBuddy DeepSeek` |
| API 协议 | `anthropic-messages` |
| 接口地址 | `https://api.deepseek.com/anthropic` |
| 模型 id | `deepseek-flash` |
| 显示名称 | `DeepSeek V4.1 Flash` |
| 上下文窗口 | 1,048,576 |
| 最大输出 | 393,216 |
| 输入类型 | 文本、图片 |
| 思考档位 | Off / Low / High / Max |

首次默认 **High**；之后你在界面里改过的档位会保留，重启不会重新写回 High。

### 5.3 新增、修改、删除

- **新增提供商**：设置 → 模型 → 添加自定义提供商，填名称、API 协议、Base URL、模型 id、显示名称、上下文与输出上限。
- **新增模型**：在同一提供商下添加模型；模型 id 必须与服务端一致。
- **修改**：直接编辑字段并保存；下一次请求生效。
- **删除**：删除前先确认没有会话还在使用该提供商/模型；删除后相关会话下一轮会失败，需要重新选择默认模型。
- 配置写在 `.studybuddy/home/profiles/desktop/cordis.patch.yml`；启动器只在文件不存在时写首次默认值，**不会覆盖你的后续修改**。

### 5.4 思考档位怎么选

| 档位 | 适合 |
| --- | --- |
| Off | 简单问答、格式转换，追求速度 |
| Low | 日常答疑、短文本整理 |
| High | 默认；数学/代码/多步推理 |
| Max | 复杂规划、长材料分析；更慢、更贵 |

档位是请求参数，不会改变学习数据；切换后下一轮对话生效。

### 5.5 API Key 的保存与首次导入

- API Key 由 `platform/windows-credentials` 使用 Windows DPAPI `CurrentUser` 加密，保存在 `<数据根>/home/credentials.dpapi`。
- 模型配置只保存**凭据引用**（`STUDYBUDDY_DEEPSEEK_API_KEY`），不保存 Key 明文。
- 首次初始化（`home/model-bootstrap.json` 不存在时）只会导入一次：设置 `STUDYBUDDY_IMPORT_CREDENTIALS` 指向一个 DSH 凭据文件，启动器从中读取 `DEEPSEEK_API_KEY` 写入 DPAPI；未设置时不会扫描其它历史凭据文件。
- 旧 A02 证据路径已删除，不再作为自动导入来源。导入成功后写 `model-bootstrap.json`；之后**不会再次自动导入**，删除 Key 后也不会被旧文件悄悄恢复。
- 加密文件只能由原 Windows 用户解密。换用户、换机器或重装系统后，需要重新填写 Key。

### 5.6 没有 Key 时能做什么

| 功能 | 无 Key 时 |
| --- | --- |
| 工作台、番茄钟、计划页、提醒、成果、问答记录、记忆 | 可用（本地数据与规则） |
| 创建计划 → 手动写草案 | 可用，不需要模型 |
| 创建计划 → 让助手规划 | 不可用；页面会提示助手暂不可用，仍可改用手动草案 |
| 对话答疑、学习分析请求、创造模式 | 不可用 |

欢迎页可以点「稍后配置」先进入应用；聊天需要 Key 时再补。

### 5.7 为什么没有账号登录

项目在部署策略里禁用了 DeepSeek 账号、账号模型适配器、账号页面与相关遥测，启动器也设置 `DSH_DESKTOP_ACCOUNT_ENABLED=0`。因此不会出现账号登录/订阅引导；模型能力完全走自定义提供商 + API Key。

## 6. 数据、备份与恢复

### 6.1 数据根里有什么

| 路径 | 内容 | 是否关键 |
| --- | --- | --- |
| `study/study.db`（+`-wal`、`-shm`） | 目标、材料、任务、时间块、计划与修订、进度、成果基础数据、记忆、问答记录、提醒状态 | **最关键** |
| `study/memory.v1.backup.json` | 记忆从 v1 文件迁移到 SQLite 前的备份（只读保留） | 建议保留 |
| `study/exports/` | 应用内导出的 JSON | 可选 |
| `home/profiles/desktop/cordis.patch.yml` | 模型、提供商、默认档位 | 重要 |
| `home/credentials.dpapi` | DPAPI 加密的 API Key 与凭据记录 | 重要但**换用户不可解密** |
| `home/cordis.patch.yml` | 启动器管理的账号/存储/插件策略，每次启动重写 | 由启动器维护 |
| `home/skills/study-creator/` | 每次启动复制的 Creator 参考 | 可重建 |
| `workspace/`、`agents/` | DSH 工作区文件与 Agent 数据 | 视使用情况 |
| `logs/`、`electron-user-data/` | 日志与 Electron 配置/缓存 | 排错用 |
| `launch.json` | 本次启动的端口与 pid，每次启动重写 | **不备份** |

> 记忆的当前主存是 `study.db` 中的 `study_memory_item` / `study_memory_evidence` / `study_memory_tombstone` 三张表；旧数据根若还有 `memory.json`，启动时会迁移并保留 `memory.v1.backup.json`。冷备份按整份数据根复制的语义与边界见 [`docs/backup.md`](../backup.md)。

### 6.2 什么需要备份

- 日常只需整份冷备份数据根，**不要手工只复制 `study.db`**：WAL 模式下单独复制可能拿到不一致的快照。
- `home/` 一起备份，才能保留模型设置与凭据引用。
- `launch.json` 有意不备份；恢复后由启动器重建。
- 备份目录不要放进数据根内部，脚本会拒绝。

### 6.3 冷备份

先**完全关闭应用**（窗口关闭、启动器退出、无 `electron.exe`），然后：

```powershell
node scripts/backup-studybuddy.mjs
```

默认备份到 `%USERPROFILE%\StudyBuddy Backups`。换目录：

```powershell
node scripts/backup-studybuddy.mjs --out "E:\StudyBuddy Backups"
```

指定另一个数据根：

```powershell
node scripts/backup-studybuddy.mjs --data-dir "D:\StudyBuddyData" --out "E:\StudyBuddy Backups"
```

成功时退出码 0，并输出 JSON 摘要（备份目录、文件数、字节数、`study.revision`、完整性检查结果）。备份目录结构：

```text
studybuddy-backup-20261110-175324/
  data/                 # 数据根副本（不含 launch.json）
  manifest.json         # 时间、来源、进程检查、每个文件的 SHA-256、数据库计数
  checksums.sha256      # <sha256>  <相对路径>
```

脚本流程：检查进程 → 记录源文件快照 → 复制 → 再次检查源快照与进程 → 比较哈希 → 在临时目录打开数据库副本做 `integrity_check` / `quick_check` → 写清单与校验文件。复制期间源数据一变就丢弃这份备份（退出码 5）。

### 6.4 校验已有备份

```powershell
node scripts/backup-studybuddy.mjs --verify "C:\Users\<你>\StudyBuddy Backups\studybuddy-backup-20261110-175324"
```

校验内容：清单格式、文件集合、每个文件大小与 SHA-256、`checksums.sha256` 与清单一致、SQLite `integrity_check`/`quick_check`、数据库修订号与各表行数。内容不一致时退出码 4；清单无法读取或格式不支持时退出码 2；校验不修改备份。

### 6.5 恢复

先关闭应用，再执行：

```powershell
node scripts/backup-studybuddy.mjs --restore "<备份目录>" --to "<项目根目录>\.studybuddy"
```

`--to` 省略时恢复到默认数据根。目标目录非空时必须显式加 `--force`：

```powershell
node scripts/backup-studybuddy.mjs --restore "<备份目录>" --to "<项目根目录>\.studybuddy" --force
```

行为：

- 脚本**先校验备份**，不通过就拒绝恢复。
- 目标非空且没有 `--force`：返回 `target_not_empty`，不改动任何文件。
- 有 `--force`：先把现有数据根改名为 `<数据根>.pre-restore-<时间>`，再复制备份的 `data/`；复制后重新比对全部哈希并检查数据库。
- 恢复后核对失败：删除刚复制的目标，把 `.pre-restore-*` 改回原名，并报错。
- 不恢复 `launch.json`；下次启动自动生成。

恢复后核对：

1. 启动应用，在对话里让助手调用 `study_status`，确认 `revision` 等于 `manifest.json` 的 `study.revision`，`database.file` 指向当前数据根。
2. 打开工作台：任务、时间块、今日/周视图应与备份前一致。
3. 打开计划页：修订号、已确认计划与进度历史应一致。
4. 打开记忆页：偏好、短期状态和删除标记应一致。
5. 若对不上，先停应用，保留 `.pre-restore-*`，不要覆盖，必要时换一份备份重试。

> v1 没有升级/迁移器。备份要**用创建它的同一版本程序**恢复；schema 不兼容时插件会拒绝启动并提示先备份。

### 6.6 导出学习数据 JSON

三个真实入口：

- **设置界面**：**设置 → 通用设置 →「导出学习数据」**（设置行 id `study.export`）。可选成果周期（当前日/周/月、今天、本周或本月）与是否包含原始学习事实，点「导出到本机」；完成后页面显示文件路径、字节数和修订号，成果服务不可用时会注明原因。
- **对话**：说“导出学习数据”，模型调用 `study_export`，文件写到 `<数据根>/study/exports/studybuddy-export-YYYYMMDD-HHmmss.json`，结果里有路径、字节数、修订号和摘要。
- **鉴权路由**：应用自身原点（同源 cookie）可 `GET /api/study/export.json` 下载同一份 JSON 附件；`POST /api/study/export.json` 接受 `{ periods, includeFacts }`，生成并写文件后返回回执。

导出内容：来源、修订号、各表行数、目标/材料/片段、任务/时间块、计划/修订/草案、进度、真实日/周/月成果快照、记忆条目与删除标记（只含 hash，不含被删正文）、变更历史、校验和。成果服务不可用时 `availability.outcomes` 会写明原因，不伪造数据；导出优先读取当前 SQLite 记忆，旧数据根没有记忆表时才回退 `memory.json`。排除：凭据、`request_log`、日志、Electron 数据、资料全文索引、原始会话与附件。

导出会做凭据扫描：一旦命中 `apiKey`、`password`、`token` 等键或 `sk-…`、`ghp_…`、`Bearer …`、私钥头等高置信形状，就**拒绝导出**并指出字段路径。若学习资料里确实有这类字符串，先删除或改写那段内容再导出。

### 6.7 备份能力的限制

- 只做冷备份：应用运行时复制不受支持，脚本会拒绝（退出码 3）。
- 没有自动定时备份、云同步或升级器；备份目录不加密，依赖磁盘/目录权限保护。
- 备份包含 DPAPI 凭据文件；跨 Windows 用户或换机器恢复后无法解密，需要重新配置 Key。
- JSON 导出不是可恢复镜像；完整恢复用冷备份。
- `request_log` 是幂等重放缓存，v1 不自动清理；冷备份完整保留，JSON 导出排除。**不要手工删表**，否则旧 `requestId` 可能在重启后被当成新请求重复写入。
- 进程检查依赖 PowerShell `Get-CimInstance`；不可用时会给 warning，并依赖复制前后的源快照与哈希比较兜底。

## 7. 界面与页面总览

### 7.1 主界面

- **左侧栏**：DSH 原生工作区/会话列表，以及学习页入口（创建计划、工作台、番茄钟、计划、提醒、今日、成果、问答记录、记忆）。
- **主区域**：默认是对话。点击某个学习页后，主区域切换为对应页面；再点回会话/对话即返回聊天。
- **页面恢复**：插件记住你最后打开的学习页，重启后自动恢复；回到对话会清空这个记录，下次仍从对话开始。
- **刷新**：页面提供「刷新」或「重试」；数据在别的页面或对话里被修改后，用它读取最新值。
- **多页面并存**：页面是主区域的互斥视图，不能与对话并排；切回对话与切回页面都是一次点击。v1 不提供常驻学习侧栏，日常以“看页面 → 回对话 → 再回页面”的方式切换。

### 7.2 页面清单

| 页面 | 主要用途 | 读写 | 需要模型 |
| --- | --- | --- | --- |
| 创建计划 | 目标 → 材料 → 计划需求；交给助手规划或手写草案 | 写 | 助手路径需要 |
| 工作台 | 今日/本周任务、时间块、进度、完成率 | 写 | 否 |
| 番茄钟 | 本地专注计时 | 写 | 否 |
| 计划 | 项目、任务日期、草案/修订、撤销、缺失信息 | 写 | 否 |
| 提醒 | 到点提醒、晚间复盘与设置 | 写 | 否 |
| 今日 | 只读诊断：修订号、存储、模块、服务时间 | 只读 | 否 |
| 成果 | 日/周/月统计、材料推进、周分析 | 只读 + 生成报告 | 否（规则生成） |
| 问答记录 | 问答单元、日摘要、主题线索、合并/拆分 | 读 + 合并/拆分 | 否 |
| 记忆 | 记忆条目 + 画像 | 写 | 否 |

### 7.3 通用操作约定

- **空态**：页面会说明“还没有数据”，不会伪造 0 或 100%。
- **错误态**：显示错误原因与「重试」；宿主未就绪时通常是“无法连接学习服务”，稍后重试或重启应用。
- **日期导航**：工作台、成果、番茄钟等页面用「前一天/后一天」「今天」「本周」「上一周/下一周」切换。
- **保存中**：按钮显示“保存中…”，期间不要重复点击；重复提交由 `requestId` 幂等保护。
- **修订冲突**：若数据在别处已被更新，页面会提示“学习数据已更新到修订 N”，可选择「重新提交」或「放弃」，不会静默覆盖。

## 8. 创建学习计划

### 8.1 准备

- 一台能运行应用的电脑；若要助手规划，需要已配置可用的模型与 Key。
- 想清楚：考试/课程名称（必填）、考试年份/日期、每天可用分钟、手边材料、固定安排或限制。
- 材料需要先导入（见 17.5）；没有材料也能创建计划。

「创建计划」**不会自动弹出**，从左侧栏进入。

### 8.2 三步引导

页面顶部是步骤指示：

1. **目标**：填考试/课程名称（必填），可选考试年份、考试日期、每天可用分钟、备注，并关联一个或多个 DSH 工作区（只记录关系，不移动文件）。
2. **材料**：勾选已经导入的材料；没有可继续。缺失版本/目录/页码/章节会标出，但不会阻止继续。
3. **计划需求**：计划标题、想达到的阶段效果、每天可用分钟、固定安排或限制、其他说明。这里只需写你确定的部分。

每一步都可以「上一步」「继续」「稍后继续」「先不创建」。底部还有「刷新」。

### 8.3 让助手开始规划

在计划需求页填写后点 **「让助手开始规划」**：

1. 应用会新建一段对话，把你的表单快照与规划指令一起注入第一轮；页面不会自己排时间。
2. 助手先读目标与材料，然后每次问你一两个问题：考试范围、当前进度、薄弱章节、每周可投入时间、固定课程等。
3. 助手会提出 **2–5 个项目**（练习册、章节学习、复习等），给每个任务分配**日期**，但**不写具体钟点**；排不下时会先和你讨论取舍。
4. 助手把草案提交到计划服务后，回到「创建计划」页点「刷新」，页面会进入草案/确认视图；也可以到「计划」页查看并确认。
5. **确认前不会改变正式安排**；草案只是草案。

如果页面提示“助手暂时不可用”，说明模型/Key 未配置或服务不可用，改用手动草案即可。

### 8.4 不用助手，自己写草案

在计划需求页点 **「不用助手，自己写草案」**：

- 计划标题（必填；有目标时自动填“「考试名称」学习计划”）。
- 可选一条起始任务：任务标题、预计分钟、安排日期、当天可用分钟、材料来源。
- 不填日期就是“未安排”，服务会把它列为待排工作，不会假装排得下。
- 保存后草案仍不会改变正式安排；确认动作在草案/确认视图里完成。

### 8.5 确认与试行

草案/确认视图会显示：

- 草案条数、预计分钟；
- 与正式计划的差异（新增/调整/移除）；
- 容量结论：排得下 / 部分未知 / 超出容量 / 尚未检查；
- 未安排条目数量与分钟；
- 风险清单。

确认规则：

- 容量足够且没有重叠：点「确认正式计划」即可，追加一条正式修订。
- 超出容量或时间重叠：必须勾选“我知道这是试行安排，会在复盘时调整”，并可填复盘日期（默认 7 天后或考试期限，取较早者），否则确认按钮不可用。
- 试行状态会一直显示，不会假装已经排得下；到复盘日期要调整。
- 确认成功后显示“已确认，正式修订 N”，可以「打开「计划」面板」或「再创建一份计划」。

### 8.6 跳过与稍后继续

- **「稍后继续」**：把当前步骤与表单保存在本机（`localStorage`），下次打开从该步骤继续；Web Storage 不可用时会明确提示“重启后不会记住”。
- **「先不创建」**：只写本地跳过状态，不创建目标、草案或正式计划；工作台、番茄钟、计划页仍可正常使用，不需要模型或网络。
- 页面不会因为“跳过”而隐藏其它入口；之后可随时重新进入创建计划。

### 8.7 创建之后怎么改

- **改日期、项目、任务**：在对话里让助手提出修订草案，然后在「计划」页确认/应用；或在计划页对已有草案操作。
- **改具体时间**：工作台添加/编辑时间块；计划只负责日期。
- **撤销最近一次修订**：计划页「撤销最近一次修订」，会追加一条新修订，学习记录不会被删除。
- **改目标**：当前界面没有目标切换栏；需要新目标时重新走创建计划，或让助手通过 `study_goal` 更新。

### 8.8 创建计划常见问题

| 现象 | 原因/处理 |
| --- | --- |
| 助手规划后页面没变化 | 点「刷新」；草案由对话提交，页面不自动轮询 |
| 找不到刚才那段创建对话 | 在 DSH 会话列表里找；创建页没有“继续上次创建对话”入口 |
| 确认按钮不可用 | 容量不足/重叠未勾选试行确认；或信息缺失被拦截 |
| 只写了考试名称也能继续 | 设计如此：年份/日期/每日分钟都可后补，缺失信息会在计划页列出 |
| 草案确认后工作台没任务 | 确认后任务才会物化；先刷新工作台；若仍没有，检查是否确认成功（计划页修订号） |

## 9. 工作台

工作台是日常执行的主页面：左边/上方是时间安排，任务是计划确认后物化出来的执行实体。它同时提供「今日」「本周」两种视图，以及「完整」「缩略」两种显示。

### 9.1 视图与切换

- **今日 / 本周**：顶部切换；用「前一天/后一天」「今天」「上一周/下一周」导航。
- **完整显示**：显示任务、时间块、进度、完成情况、今日/本周计划分组。
- **缩略显示**：只展示今天的安排与今日计划，适合快速扫一眼；需要任务/时间块/进度时切回完整。
- 显示偏好保存在本机，重启后保留。
- 顶部汇总：学习安排（块数/分钟）、固定课程（单独计算）、任务数；固定课程与休息**不计入学习完成量**。

### 9.2 任务

点「新增任务」填写：

| 字段 | 说明 |
| --- | --- |
| 任务名称 | 必填 |
| 学科 | 可选，用于问答记录/成果的学科归类 |
| 预计工作量（分钟） | 非负整数 |
| 材料 | 自由文本位置，例如“数学分析 第三版 第3章 第2节”；不会自动映射成资料库 id |
| 完成条件 | 例如“做完 1-20 题并订正错题” |
| 前置任务 | 可选；用于表达依赖关系 |

操作：

- **编辑任务**：任务行「编辑任务」。
- **换书/更换材料**：用「替换任务」新建一个任务并让旧任务退休；旧任务的历史进度保留、新任务不继承进度，其他任务里指向旧任务的前置关系会改指新任务。直接改已有任务的「材料」字段会被拒绝并提示用替换。
- **删除任务**：确认后软删除；已排的时间块会保留，并标记“任务已删除”，历史不会消失。若仍有活动任务把它当前置，删除会被拒绝并返回冲突。
- **快捷入口**：任务行还有「问这道题」（见 17.3）和「开始番茄」；后者带该任务直接启动番茄钟，计时不改变任务状态（见第 10 章）。
- **任务来源**：计划确认后物化的任务会带项目、计划日期；手动新建的任务没有这些字段。

### 9.3 时间块

时间块描述“哪天几点到几点做什么”，是提醒、计时关联和实际执行的基础。

点「添加时间块」填写：

| 字段 | 说明 |
| --- | --- |
| 日期 | 本地日期 |
| 开始 / 结束 | `HH:MM`；结束必须晚于开始；**不支持跨夜**，跨夜请拆成两个块 |
| 关联任务 | 可选；关联后提醒、进度、计时都能对上任务 |
| 标题 | 不关联任务时必填，例如“高等数学课” |
| 备注 | 可选 |
| 固定（课程/休息，不计学习） | 勾选后进入“固定课程”汇总，不进入学习分钟与完成量 |

操作：

- **编辑/删除**：时间块卡片上的按钮；删除是硬删除，历史通过追加式变更日志保留。
- **拖动改期**：周视图把块拖到某一天的卡片；日视图可把块拖到具体开始时间（保持原时长，同一天也能改时段），或拖到“前一天/后一天”投放条。拖拽只改选中块的日期/开始时间，不改任务、标题、备注或任务 id。
- **重叠**：同一时间与另一个块重叠时，先提示，保存时要求「仍然保留」或「取消」；首尾相接不算重叠。固定课程也算占用，不能把学习块静默盖在课上。
- **计划日期 vs 时间块日期**：计划分配的日期是“原定意图”，时间块是“实际执行”；拖块到另一天不会改写计划分配日期，页面可能同时显示两者。

### 9.4 记录进度与完成率

在任务行点 **「记录进度」**：

| 字段 | 说明 |
| --- | --- |
| 状态 | 未开始 / 进行中 / 部分完成 / 完成 / 取消 |
| 已完成数量 / 总数量 | 非负整数；完成时已完成不能小于总数 |
| 文字反馈 | 例如“做了 1-8 题，第 7 题不会” |

规则：

- 页面记录的进度默认视为**已确认**；助手的推测可能标为“待确认”，你在页面上重新记录一次即成为已确认。
- **取消**不进入完成数，但留在计划分母里；待确认不算完成；未记录不等于未学习。
- 完成率 = 已确认完成 / 计划任务数；取消不会抬高完成率。只有没有任何任务时显示“还没有计划任务”，不会伪造 100%。
- 同一状态/数量/文字的重复提交返回已有记录，不重复追加。
- 并发冲突时页面回滚乐观状态并提示“重新提交”或“放弃”，重提会用新的修订号。

### 9.5 今日计划 / 本周计划

- 计划确认后，任务按计划分配的日期进入「今日计划」或「本周计划」组，显示项目徽标、计划日期与完成条件。
- 点「安排时间」会打开时间块表单并**预选该任务**；填开始/结束即可。
- 计划外的任务仍在「已安排」或「其他任务」里，不会被隐藏。
- 缩略显示也有一张「今日计划」卡，提示具体时间到完整工作台安排。

### 9.6 保存失败的排查

| 提示 | 含义 | 处理 |
| --- | --- | --- |
| 学习数据已更新到修订 N | 你在编辑期间别处已写入 | 「重新提交」读取最新修订后重试；或「放弃」 |
| 与 N 个时间块重叠 | 时间冲突 | 改时间，或明确「仍然保留」 |
| 保存失败，已恢复原状态 | 网络/服务错误 | 检查宿主是否就绪，重试；必要时「刷新」 |
| 删除失败，已恢复原状态 | 同上 | 重试；若因前置依赖被拒，先处理依赖任务 |

## 10. 番茄钟

### 10.1 设置默认时长

- 学习时长（分钟）：默认 25，可设 1–180。
- 休息时长（分钟）：默认 5，可设 1–180。
- 点「保存默认时长」后，新的计时使用新默认值；本次计时也可以单独改时长。

### 10.2 开始计时

1. 选「学习」或「休息」。
2. 填本次时长（1–180 分钟）。
3. 可选关联任务；不关联也能计时。
4. 点「开始」。

也可以从工作台任务行点「开始番茄」：会带该任务直接启动学习计时。

计时只记录专注时间，**不会改变任务状态**。关联任务只是让计时记录能对上任务，不代替进度记录。

### 10.3 计时中

- **暂停 / 继续**：暂停期间不计入专注时长。
- **结束**：提前结束，记为“提前结束”。
- 到点后记为“已完成”，可点「记录本次专注」。
- 页面显示“专注 X · 计划 Y”、剩余时间、关联任务。
- 计时不等于完成：结束后请到工作台/计划页记录任务进度。

### 10.4 中断与重启

- 应用关闭、休眠或长时间无心跳后，计时会被标记为“已中断”。
- 重启后页面显示“计时中断了 N 分钟，这段时间不计入专注时长”，并提供「继续（跳过中断）」或「结束并记录」。
- 中断确认前，暂停/继续/结束操作会被拒绝，避免把中断时间算进专注。

### 10.5 通知与边界

- 若启用了学习系统通知，番茄到点会发一条系统通知（标题 StudyBuddy，正文“Pomodoro finished”），应用内仍有页面状态。
- 计时依赖本地时钟与心跳；机器休眠少于 45 秒可能被计入，系统时钟回拨无法识别。
- 计时不调用模型，断网可用。

## 11. 提醒与晚间复盘

### 11.1 到点提醒

- 来源：今天的、非固定、**有关联任务**的时间块。
- 触发时机：时间块的**结束时间到了之后**，页面/横幅问一次“这项任务做得怎么样”；同一块只问一次（按块身份记账）。
- 同一时段结束的多个任务会合并成一张卡；一个任务的多个块合并为一个条目。
- 提醒只在应用运行时生效；关闭期间错过的提醒**不补发**，重启也不会重新弹旧卡。

### 11.2 快捷答复

| 答复 | 写入的进度 |
| --- | --- |
| 完成 | `done`，已确认 |
| 部分 | `partial`（可再补数量） |
| 未完成 | `not_started`，已确认 |
| 稍后 | 稍后提醒（默认 10 分钟，可设 1–120） |

答复会立即写入任务进度；写入失败时提醒保持未答复并显示错误，不会假装成功。重复答复同一结果不会追加第二条进度。

### 11.3 提醒设置

「提醒」页底部：

| 设置 | 默认 | 说明 |
| --- | --- | --- |
| 应用内提醒 | 开 | 关闭后不再弹到点提醒 |
| 晚间复盘提醒 | 开 | 到点提示复盘 |
| 静默时段 | 22:00–07:00 | 起止相同表示关闭静默 |
| 晚间复盘时间 | 21:30 | `HH:MM` |
| 稍后提醒（分钟） | 10 | 1–120 |

设置保存到本地数据库；保存失败会显示原因。

### 11.4 静默与专注延后

- 静默时段内结束的提醒**不消耗**该块的一次机会，会延后到静默结束。
- 番茄钟处于“学习 + 计时中”时，提醒延后到计时结束。
- 页面会显示“静默时段（…），提醒延后到 …”或“专注计时中，提醒延后到 …”，以及待恢复卡数。

### 11.5 晚间复盘

到复盘时间后，顶部横幅提示；也可以在提醒页点「现在复盘」手动开始。

1. **读取方案**：读最新计划与进度，处理 `date <= 今天` 且**弹性**的计划条目；固定安排、已完成、已取消与 `date: null` 的未安排条目不动。未记录或待确认的剩余工作量也会参与拆分，并作为暂定块写入修订（块上带 tentative/assumption 标记），不会被当成已完成；部分完成且有数量时按剩余比例折算分钟。
2. **预览**：显示要移动的条目、目标日期、开始/结束与分钟数；保留未安排的条目会列出原因（后续日期没有容量、可用时间未知、期限前没有更晚日期）。
3. **保存调整**：点「保存调整」才会写入一条计划修订；未确认的手动草案优先，存在未确认草案时复盘会被阻止。
4. **完成**：显示“已保存计划修订 N”，可在计划页撤销最近一次修订。

不会自动移动的情况：固定安排、已完成、已取消。复盘会把剩余工作量拆分到次日起 7 天（或考试期限前，取较早者）的空闲时段，可跨日拆成多个块；未记录/待确认的剩余量也会按暂定块写入（块上带 tentative/assumption 标记），不会被当成已完成。复盘不改预算、不改目标，排不下就保留未安排并说明原因。

复盘常见阻断：

| 提示 | 含义 | 处理 |
| --- | --- | --- |
| 计划还有未确认的手动草案 | 手动修改优先 | 先在计划页确认或丢弃草案 |
| 计划尚未确认 | 没有正式修订可调整 | 先确认计划 |
| 还没有已确认的计划 | 无计划 | 先创建并确认计划 |
| 没有需要调整的剩余弹性任务 | 没有符合条件的条目 | 无需操作 |
| 待调整：… | 保存时被容量/依赖/过期拒绝 | 按提示调整计划后重试 |
| 复盘没有保存：… | 服务错误 | 重试；必要时刷新计划 |

### 11.6 系统通知

- 到点提醒、番茄完成、晚间复盘可发系统通知；权限被拒绝时只显示应用内提示，并明确说明。
- 在提醒页/番茄钟页点「启用学习系统通知」请求权限；拒绝后不会反复弹。
- Windows toast 的可见性受系统通知设置、专注助手、AppUserModelID 等影响；**应用内横幅才是兜底**，不要把系统通知当作唯一验收标准。

### 11.7 回复完成提醒

这是另一类提醒，和到点学习提醒独立：

- 入口：**设置 → 通用设置 → 「回复完成时提醒」**，默认开启。
- 作用：你在别的界面时，助手回复结束提醒一次；应用关闭不提醒。
- 你正在看的那条会话（主视图）不提醒；切到学习页或别的会话后才提醒。
- 1.2 秒内的多个完成会合并成一条；页内提示条约 8 秒自动消失，也可「知道了」。
- 系统通知权限被拒绝/不支持时，页内提示条照常出现，并写明降级原因。
- 关闭该设置会立即清空待发窗口与已显示条目；设置保存在本机，重启后保留。

## 12. 计划页

### 12.1 它显示什么

计划页是“正式计划”的只读展示面，加上少量写操作（确认草案、应用修订、撤销、记录条目进度）。它不负责创建（创建在「创建计划」），也不负责排具体钟点（在工作台）。

页面区域：

- 计划头：标题、状态（草案/已生效/试行中）、正式修订号、条目数与分钟、项目数、未安排数。
- 试行提示：复查日期与风险。
- 缺失信息：目标字段、任务、项目、阶段/周目标、可用时间、未安排条目、未核实材料定位、失效材料、草案未确认。
- 草案卡：未确认草案的条数、差异、确认入口。
- 阶段与周目标。
- 项目卡。
- 任务安排：按项目、再按日期分组；未安排单列。
- 进度记录：未记录/完成/待确认/取消。
- 修订记录：每条修订的原因、时间、差异；只有最近一次可撤销。
- 容量与风险。

### 12.2 项目

项目随计划草案/修订产生，类型包括练习册、章节学习、课程、复习、其他；卡片显示任务数/分钟、日期范围、目标、备注、关联材料。

没有独立项目 CRUD：新增/修改项目要改草案（让助手提修订，或手写 payload），学生侧主要通过确认/撤销和任务编辑来调整。

### 12.3 任务与日期

- 每个任务显示计划日期、预计分钟、科目、来源（学生/助手/系统）、前置任务、完成条件、备注。
- 未安排条目显示“未安排”，并提示“这些工作还没有日期，不会假装已经排进某一天”。
- 具体钟点不在这里排；条目会提示“还没排具体时间 · 到工作台安排”。
- 材料来源可展开：显示资料标题、类型/版本/科目、导入来源、章节/页码/题号，以及未核实字段；找不到资料时直接显示“找不到资料 {id}”。

### 12.4 草案、确认、修订、撤销

- **确认草案**：草案存在时，页面提供「确认」；若计划已有正式修订，则是「修订」（应用草案为一条新修订）。容量不足/重叠时要求确认试行。
- **差异**：显示新增/调整/移除数量；字段级差异可展开（标题、学科、材料、定位、时长、日期、开始/结束、弹性、完成标准、前置、项目、备注）。
- **撤销**：只对最近一次正式修订可用；撤销会追加一条新修订，把安排恢复到上一次状态，**不删除学习记录**。
- **草案保护**：存在未确认草案时，撤销/修订必须带上草案 ID，避免静默丢弃你刚改的草案；页面会显示提示。

### 12.5 缺失信息与容量

- 缺失信息不是错误，是“还缺什么”的清单；可逐项补，不影响继续使用。
- 容量结论：排得下 / 部分未知 / 超出容量 / 尚未检查；未知天数与未安排分钟会单独列出。
- 试行计划的复查日期、风险会一直显示，直到你调整并产生新修订。

### 12.6 条目进度

任务行提供进度操作（未开始/进行中/部分完成/完成/取消）；「部分完成」会询问已完成数量与总数量。这里的进度与工作台是同一套任务进度，任一处记录都会在另一处反映。

## 13. 成果

### 13.1 视图

- 日 / 周 / 月三种模式；用「前一天/后一天」「上一周/下一周」「上个月/下个月」和「今天/本周/本月」导航。
- 顶部显示当前区间。
- 页面只读，不写学习数据；“生成/刷新分析”只写报告行。

### 13.2 三种口径

| 口径 | 含义 |
| --- | --- |
| 原计划 | 周期开始时的计划：任务取当天首次打开应用写入的日快照（缺失时按午夜从变更日志重建）；计划条目取午夜前已应用的修订 |
| 调整后 | 当前时间块 + 周期结束前已应用的最新修订；过去周期冻结在期末，不追溯之后的修订 |
| 主动取消 | 取消数量及占计划的比例；**不是完成率**，单独列出 |

规则：

- 两份完成率的分母都保留已取消项，所以取消**不会抬高**完成率。
- 待确认不算完成；未记录显示为“未记录”，不推断成未学习。
- 同一任务/计划条目在周/月内只计一次；跨天重排不重复累计。
- 没有可计算分母时显示“没有可统计的计划”，不伪造 0% 或 100%。

### 13.3 按天与明细

- **按天查看**：日期、原计划完成/计划、调整后完成/计划、记录数、材料数；按天行是当天计划槽位视图，**不可直接相加**得到周期合计。
- **明细**：任务/计划条目、原计划/未排计划徽标、计划日期、记录日期、数量、状态（未记录/未开始/进行中/部分完成/完成/主动取消/待确认）。
- 已删除条目标注“已删除”；任务软删除仍保留在原计划分母，避免用删除代替取消来美化完成率。

### 13.4 材料推进

- 只统计周期内**已确认**且状态为部分完成/完成的条目。
- 计划条目按 `materialId` 归并为“推进条数 / 材料份数 / 条目与记录日期”。
- 任务里的材料字段是自由文本，只作为“任务里记录的材料位置”单列，不猜测对应资料 id、不映射成库内材料。
- 取消、待确认、未开始不计；固定课程/休息与无任务标题块完全不进统计。

### 13.5 本周学习分析

在周模式、统计表下方有“本周学习分析”卡：

- 显示 3 条要点；
- 「生成本周分析」/「刷新分析」：按本周问答、方法信号、弱主题证据用规则生成，**不调用模型**；
- 「展开完整报告」/「收起完整报告」：报告固定四段——我看到的、我的解释、建议你试的、需要你确认的；
- 没有报告时只显示生成按钮，不自动生成；
- 报告标“规则版 · 本地生成”，来源是你自己的记录。

报告可能包含：弱主题排序、方法信号（同类反复、时段低效、集中突击、未闭环积压）、画像变化、最近日摘要引用。每条信号都有反证，不把“可能”说成结论。

### 13.6 口径限制

- 历史周报的弱主题/信号使用**当前**的 90 天/30 天窗口计算，回看很旧的报告时，解释部分可能反映之后的数据。
- 主题聚类对“同 subject 但 top token 相同”的不同簇可能合并，名称截断后可能撞名。
- 重问检测在 90 天正文清理后只能靠 sketch 相似度，不能声称“同一题”。
- 报告统计里“闭环/未闭环”按单元数，“题目数”按题目行，两者不互相换算。

### 13.7 完成反馈与里程碑

学习和复盘之外，应用还会用不打断操作的方式给一点反馈：

- **完成提示条**：你记录一条“完成”后出现“已记录完成：标题”，约 6 秒自动消失，也可「知道了」。
- **阶段卡片**：周/月里程碑或阶段小结，显示本周/本月完成数、完成率、材料推进、下一步建议；约 30 秒自动消失，可「知道了」。
- **里程碑**：本周第一条完成、完成 3 项、完成 5 项、完成计划条目、完成记录关联材料；本月第一条、10 项、20 项、3 条计划条目、2 份材料。只统计**已确认完成**，取消/待确认/部分完成不算。
- **个人里程碑**：成果页底部「个人里程碑」可关联 1–100 个任务定义阶段成果；只有关联任务出现**已确认完成**记录才算达成，取消/待确认不计。列表显示完成数/总数与达成日期，可展开看证据（任务 id、进度记录 id、日期），也可移除定义。
- **口径**：不计算连续打卡，不因中断扣分；不排名、不分享、不发徽章；每个周期只弹一次；每周期开始时只做基线，不会把打开页面前已有的完成记录当成“新成就”。
- 应用关闭时不反馈、不补发；英文界面下卡片正文可能仍是中文（服务端文案限制）。

## 14. 问答记录

### 14.1 自动记录什么

- 你在对话里发送的**文字**提问会被自动捕获（`source.kind === 'user'`）；注入的上下文、助手的回复不进入问答单元。
- 捕获后按规则分类（反馈/问题/计划/情绪/闲聊），并把同一会话里的连续提问切分成“问答单元”；每单元通常包含 1–3 道关联题目。
- 单元会识别结果信号：已理解、困惑、独立解出、放弃、重问，并据此给出闭环状态（已闭环/未闭环/未判定）。
- 纯图片/文件、没有文字正文的消息不会入单元；这是当前已知缺口。
- 捕获失败不会打断对话，会写入缺口记录；页面不会因此报错。

### 14.2 学习日窗口与摘要

- 学习日按本地 **04:00** 切分：04:00 前算前一天；窗口是本地 04:00 到次日 04:00。
- 窗口结束后自动封口，并生成**规则摘要**（不调用模型）：问答次数、题目数、闭环/未闭环、重问、学科分布、未闭环题目与困惑点。
- 页面顶部显示：当前窗口、待封口/待摘要数量、最近 3 条日摘要、主题线索（按学科聚合最近 30 天）。
- 超过 14 天的窗口不再补做，会标注“超过 14 天补做上限”；失败会重试并提示。
- 日摘要正文目前是中文模板；英文界面下仍显示中文正文。

### 14.3 筛选与详情

- 时间范围：近 7 天 / 近 30 天（服务端按日期过滤）。
- 学科：全部学科 / 已知学科并集 / 未分类。
- 闭环状态：全部 / 已闭环 / 未闭环 / 未判定。
- 关键词：搜索题目或回合正文；会同时匹配单元内回合。
- 列表：时间、学科、题目摘要、闭环状态、重问次数、已合并徽标。
- 详情：题目、回合（角色：提问/追问/确认）、信号；没有信号时明确显示“还没有结果信号”。

### 14.4 合并与拆分

- **合并**：勾选 ≥2 个同一备考目标、都未合并的单元，点「合并所选」；合并后回合/题目/信号/主题归到最早的单元，源单元标“已合并”。日摘要会失效并在下次重算。
- **拆分**：在详情里对某个回合点「从这里拆开」；该回合及之后的回合、题目、信号移到新单元。**不能从第 1 个回合拆**（原单元会变空）。
- 合并/拆分都会写变更日志，并让相关日摘要重新生成；不会删除历史。

### 14.5 90 天正文保留

- 超过 90 天的回合正文、题目正文与规范化文本会被清空；hash、sketch、状态、单元摘要、统计与主题关联保留。
- 页面会显示“正文已按 90 天保留策略清理，摘要与统计仍保留”；单个已清理回合也有提示。
- 清理在启动时跑一次，之后每 24 小时一次；不删除行、不写墓碑。

### 14.6 限制

- 只捕获文字；纯附件消息不入库。
- 切分是规则版，可能把“任务会话里的闲聊”并入学习单元，也可能把一次多问题拆成多个单元；用合并/拆分纠正。
- 日摘要、主题线索、闭环判断都是规则或模板，不是模型判断；不要把它当成能力评估。
- 合并/拆分后旧摘要会重建，但历史版本不会在页面上留档。

## 15. 记忆与画像

### 15.1 记忆是什么

记忆页只保存三类学生事实：**偏好**（长期）、**短期状态**（默认 7 天过期）、**待确认观察**。它不保存计划、完成量或学习统计——那些在计划/成果/问答记录里。

### 15.2 类型、来源与过期

| 类型 | 用途 | 过期 |
| --- | --- | --- |
| 偏好 | “我更喜欢上午学数学” | 不过期，除非删除/纠正 |
| 短期状态 | “这周在准备期中考试” | 默认 7 天；可设 1 分钟–90 天 |
| 待确认观察 | 助手从对话里观察到、但还需要你确认的内容 | 可设有效期；未设则长期保留 |

页面显示类型、来源、更新时间、到期时间；已过期的默认隐藏，可勾选「显示已过期」。列表还会标出每条记忆的作用域：**学生偏好**（只存长期偏好）、**目标记忆**（绑定当前目标）、**临时会话**（只在写入它的会话召回）。作用域由服务端校验，跨目标/跨会话不会串入。

### 15.3 新增、纠正、删除

- **新增**：在输入框写一句话（≤500 字），点「记住」；也可以直接对助手说“记住……”。
- **纠正**：点「纠正」修改正文，旧版本被取代（`superseded_by`）但保留历史；召回只用当前版本，旧证据不会重建旧结论。
- **删除**：确认后写入删除标记（只存内容 hash，不存被删正文）；之后不会再被召回，也不会被旧对话内容重建。
- 只有你本人（界面）可以显式恢复一条被删除的同内容记忆；助手不能绕过删除标记。
- v1 上限：记忆 200 条、正文 500 字、删除标记 500 条。

### 15.4 画像：六项讲解参数

「记忆」页切到「画像」tab：

| 参数 | 作用 | 默认 | 自动推断 |
| --- | --- | --- | --- |
| 讲解详细度 | 结论/推导/例子/前置知识的展开程度 | 3/5 | 是 |
| 提示偏好 | 先提示还是先答案 | 0.5 | 否，仅显式 |
| 推进速度 | 放慢/正常/加快 | 0 | 否，仅显式 |
| 例子顺序 | 先定义还是先举例 | 0.5 | 否，仅显式 |
| 步骤粒度 | 合并/分点/一步一编号 | 2 | 否，仅显式 |
| 确认频率 | 讲完确认/每段/每 2 步 | 1 | 否，仅显式 |

每行显示：参数名、行为描述、当前档位、`依据 N 次问答`、手动设置徽标（如适用）、「降一档」「升一档」「恢复默认」。

### 15.5 自动推断、纠正与衰减

- 自动推断目前只对**讲解详细度**生效：重问（7 天内）作为“需要更细”的正证据，干净闭环作为负证据；用 Beta 公式折算置信度。
- 置信度 ≥0.70 才自动生效；首次生效还要求 ≥3 个独立单元且证据跨度 ≥14 天。
- 自动推断**不会低于默认档 3**，避免“学得好反而讲得更少”。
- 7 天内最多自动变 1 档；超过 8 周没有新证据会原地回落到默认档。
- 你手动调整后**立即生效**，且纠正后的推断只使用纠正之后的新证据；要重新被自动推断取代，需要 ≥3 个新单元且跨度 ≥14 天。
- 没有删除/否认参数的入口；只有降/升/恢复默认。

### 15.6 讲解契约怎么生效

- 有非默认参数时，系统会在下一轮对话注入一段“【讲解契约】”，例如“详细度 4/5（补前置 + 推导 + 例子）；解题先给提示再给答案；推进速度偏慢”。
- 契约只写参数，不写证据 id、置信度或“为什么”；默认档不写，所以改回默认会让对应子句消失。
- 契约是**讲解假设，不是评价**，不会降低任务要求；助手不应复述这段，也不应据此放宽标准。
- 没有非默认参数时回退到旧的记忆快照（最多 8 条、每条 120 字）；有参数时相关记忆最多 4 条、每条 50 字。
- 契约在参数变化后的下一轮生效；同一会话内 DSH 只在文本变化时写快照，不会每步重复注入。

### 15.7 限制

- 记忆正文是中文数据，英文界面下仍显示原文（不翻译记忆）。
- 召回是中文词法（字符 + bigram + 拉丁词），不是语义检索；不要声称“理解”。
- 记忆/画像不写学习计划或完成量；它们只影响讲解方式。
- 迁移/读写异常时模块会进入只读回退，并提示备份文件路径；此时新增/删除会返回 `unavailable`。

## 16. 今日（只读诊断）

「今日」页是学习内核的只读视图，日常学习通常不需要打开。它显示：

- 日期、数据修订号、今日快照是否生成；
- 存储文件、日志模式、文件大小、内核 schema；
- 已加载模块、服务命名空间、服务器时间；
- 写入是否被停用及原因；
- 「刷新」。

用途：确认数据是否落库、修订号是否推进、模块是否加载、宿主时间是否正确。**不要在这里修改数据**；排错时可把页面内容截图给维护者。

## 17. 与助手协作

### 17.1 上下文从哪里来

- **本会话**：DSH 原生对话历史。
- **任务答疑上下文**：点任务行「问这道题」后，助手会带上任务标题/学科/完成条件、最多 3 条资料片段（每条 ≤240 字）、最新正式计划的少量条目（≤4 条），整段 ≤2400 字。
- **记忆/画像**：注入讲解契约或记忆快照（见 15.6）。
- **自由聊天**：不自动注入任务上下文；需要时明确说“结合任务……”或点「问这道题」。

### 17.2 常用说法与对应工具

| 你说 | 助手会调用 | 作用 |
| --- | --- | --- |
| “帮我建一个备考目标：2027 考研数学一，12 月 20 日考试，每天 240 分钟” | `study_goal` | 新建/更新目标 |
| “帮我导入材料：数学分析 第三版，第一章……” | `study_materials`（import_text） | 导入文字/Markdown 材料并建索引 |
| “找一下极限相关的资料片段” | `study_materials`（search） | 词法检索片段 |
| “按这个目标给我排一份计划，分成练习册和章节复习” | `study_plan`（draft） | 提交计划草案（不会自动确认） |
| “把这份草案确认了” | `study_plan`（confirm） | 确认草案，产生正式修订 |
| “明天做不完了，帮我把没做完的顺延” | `study_plan`（revise）或晚间复盘 | 生成/应用修订；正式重排需确认 |
| “把明天没排完的任务细化一下” | `study_plan`（refine） | 只细化指定日期的完整条目列表，不覆盖其他日期与未确认草案 |
| “这本练习册不做了，换成另一本” | `study_tasks`（replaceTask） | 新建任务并退休旧任务；旧进度保留，新任务不继承 |
| “记一下：我更喜欢上午学数学” | `memory_remember` | 写入偏好记忆 |
| “我之前说过什么偏好？” | `memory_recall` | 按关键词/类型召回 |
| “忘掉关于晚上学数学的那条” | `memory_forget` | 删除并留删除标记 |
| “讲细一点 / 多给我提示” | `memory_profile` | 调整画像参数 |
| “我今天数学做了 1-8 题，第 7 题不会” | `study_progress` | 记录任务进度（可能标待确认） |
| “我这周哪些题老出错？” | `study_questions` / `study_insight` | 问答检索 / 弱主题分析 |
| “生成本周学习分析” | `study_insight`（review_save） | 生成并保存规则版周报 |
| “导出学习数据” | `study_export` | 写 JSON 到 `study/exports/` |
| “这道题怎么理解？”（已点「问这道题」） | `study_tutoring` | 带入任务、材料、计划上下文 |

> 工具名是内部实现，你不需要记；用自然语言说清楚要做什么即可。涉及写入时，助手应带上幂等标识，并在冲突时让你重试。

### 17.3 「问这道题」

- 工作台任务行有「问这道题」（英文 `Ask about this task`）。
- 点击后会把当前任务关联到会话，并把任务、可核对的资料片段、最新正式计划注入下一轮。
- 同一任务、同一内容重复点击不会重复注入；任务/资料/计划变化后需要显式刷新（助手侧 `refresh: true`，或重新点一次）。
- 让助手解除任务关联不会删除已有聊天记录；自由聊天不会继续带任务上下文。
- 资料片段是词法线索，可能漏掉语义相关但用词不同的内容；找不到时会明确写“没有找到相关资料片段”。

### 17.4 计划与进度

- 助手可以**提交草案**，但确认/应用修订要经过你（页面按钮，或你明确授权后的工具调用）。
- 助手记录进度时，如果只是推测会标“待确认”；你需要在页面/对话里确认或重新记录。
- 晚间复盘的重排**必须你点保存**；v1 没有“无人确认自动重排”的授权。
- 计划修改会保留修订历史；撤销只撤销最近一次，且不会删除学习记录。

### 17.5 材料导入与检索

- 当前界面/模型工具支持**文字或 Markdown** 导入：助手调用 `study_materials` 的 `import_text`，按标题、版本、学科、章节建片段与词法索引。
- 材料需要先导入，创建计划的材料步骤才能勾选。
- PDF 解析在服务层（`materials.importFile`）已实现，但**当前没有面向学生的界面/工具入口**；这是 v1 限制。需要 PDF 时，先把可复制的文字贴进对话让助手导入。
- 检索是词法 bigram，不是向量语义；查询不足两个字符时走整串包含匹配。
- 定位（页码/章节/题号）只记录来源能证明的内容；无法核实的会标“未核实”，不猜页码、不猜题号。

### 17.6 学习分析

- 在对话里说“分析我最近的弱项”“我有哪些不好的学习习惯”，助手会调用 `study_insight` 返回带引用的弱主题/方法信号。
- 周报固定四段，建议 1–3 条，每条带“怎么判断有效”；不出现能力/心理诊断。
- 所有分析基于你自己的记录，规则生成，不调用模型；不会把“没记录”当成“没学习”。

### 17.7 安全边界

- 助手只能经学习服务读写数据；不能直接打开 `study.db`、`memory.json`、`credentials.dpapi`、会话日志或 `request_log`。
- 生成的插件（创造模式）不是沙箱，与普通插件同权限；只承诺可撤销/可移除。
- 导出会拒绝疑似凭据的文本；记忆删除有墓碑，旧对话不能重建被删内容。

## 18. 创造模式

### 18.1 什么时候用

需要“以后反复打开”的页面/小工具时用创造模式；一次性表格/文件直接让助手生成文件即可。

| 模式 | 适合 |
| --- | --- |
| 标准模式 | 日常答疑、代码、文件、资料（默认） |
| PTC 模式 | 批量调用工具后筛选、整理、统计 |
| 极简模式 | 终端、读图、基础对比 |
| 创造模式 | 让 Agent 编写并安装 DSH 插件/页面/自定义模式 |

### 18.2 进入与切换

- 新建任务时在输入框上方的模式按钮选「创造模式」；或在「设置 → Agent 预设」里选创造模式。
- 默认是标准模式；创造模式**必须显式切换**，不会因为你说“做一个页面”就自动切。
- 切换只影响该会话后续请求与新建会话；已经跑过一轮的会话保持启动时的预设，Host 会拒绝中途换预设。
- 创造能力由 `@deepseek-ai/dsh-personalized-recommendations` 提供；首次启动写入 profile，之后可在「插件」页关闭。关闭后下次启动不会强行加回；要重新启用，删除 `<数据根>/home/.studybuddy-creator-enabled` 后重启，或在插件页重新打开。

### 18.3 创建卡片流程

1. 你明确要一个页面/小工具，例如“做一个按日期列出今天学习块和完成状态的清单页，放左侧，能一直打开”。
2. 助手先给方案，回答末尾出现**创建卡片**；卡片可改位置、展开预览、看“创建需要较长时间和较多 token”的说明，或点「暂不」。
3. 点 **Create（创建）** 才会启动 Creator 子 Agent 生成真实插件包；生成阶段可取消。
4. Host 校验包身份、补丁和构建入口后，复制到 profile 并以 `link:` 安装。
5. 卡片显示 **Installed（已安装）** 后，页面按你选的位置出现；关闭/离开会话不会卸载，重启仍在。
6. **Undo（撤销）** 卸载并移除界面；**Restore（恢复）** 用保留的 profile 副本重装，不重新生成。

位置：

| 位置 | 效果 | 建议 |
| --- | --- | --- |
| 会话标签页 | 当前会话 Chat/Trajectory 旁多一个标签 | 清单、图表等跟本次任务绑定 |
| 左侧全局页 | 左侧栏入口打开主区域页面 | 跨会话反复打开的记录 |
| 右侧栏 | 对话旁的窄栏 | 边聊边看；窄窗口要能压缩 |

也可以在卡片里自己写位置；无法用现有扩展点实现的位置会明确失败，不会悄悄换位置。

### 18.4 生成页面能读写什么

- 只经学习服务：浏览器 `POST /api/study/<namespace>/<method>`（同源 cookie），宿主 `ctx.study.call(...)`。
- 允许的只读命名空间：`kernel`、`tasks`、`plans`、`materials`、`outcomes`、`followup`、`timer`、`memory.recall`。
- 写入只在需求明确时发生，并带 `requestId` 与读到的 `expectedRevision`；冲突时显示服务消息让你重试。
- 不得打开 `study.db`、`memory.json`、`credentials.dpapi`、会话日志或 `request_log`；不得把凭据写进页面/日志。

### 18.5 失败与恢复

| 现象 | 含义 | 处理 |
| --- | --- | --- |
| 卡片显示失败/已中断 | 生成未完成、包校验失败或安装失败 | 在卡片上重试；仍失败把说明发回对话 |
| Create 不可用 | 会话不是活的根会话、没有 profile 修改权限、只读沙箱 | 回主会话，确认不是只读模式后重开卡片 |
| 名字或位置不支持 | 方案与现有扩展点不符 | 改位置或描述后重新提案 |
| 撤销后想再用 | 已卸载 | 点 Restore；源文件仍在时无需重新生成 |
| Restore 被拒绝 | profile 副本缺失或校验失败 | 重新提案一个新页面 |
| 日常模式没有卡片 | 日常答疑不触发（设计） | 切到创造模式再要页面 |

### 18.6 限制

- 只支持新建插件，不支持在卡片里修改已有插件；没有版本历史。
- 撤销不删除源码：工作区 `.dsh-created-plugins/<id>` 与 profile 的 `created-plugins/<id>` 保留，需要时手动删。
- 生成插件与普通插件同权限，**不是沙箱**；不承诺受限执行或代码审计。
- 模型是否提议卡片取决于语义判断，不保证每次都能识别。
- DSH 升级后需要重跑创造流程冒烟（`node tests/creator/creation-smoke.mjs`）。

## 19. 开发与维护

### 19.1 构建

只改插件客户端时（把 `study-outcomes` 换成你正在改的插件）：

node plugins/study-outcomes/scripts/build-client.mjs

### 19.3 核心补丁

项目对 DSH 源码的改动集中在 `patches/`：

| 补丁 | 作用 |
| --- | --- |
| `0001-desktop-account-toggle.patch` | 桌面壳 `DSH_DESKTOP_ACCOUNT_ENABLED` 开关，跳过账号引导 |
| `0002-second-main-column.patch` | `AppFrame` 第二主栏能力（当前学习页不再注册该栏，保留为未启用能力） |

```powershell
git -C source/deepseek-harness apply --check -R "$PWD/patches/0001-desktop-account-toggle.patch"
git -C source/deepseek-harness apply --check -R "$PWD/patches/0002-second-main-column.patch"
git -C source/deepseek-harness apply --check -R "$PWD/patches/0003-desktop-tray-icon.patch"
```

升级 DSH 或重建源码后：

1. 先恢复干净工作树；
2. `git apply --3way` 重放补丁；
3. 按语义解决冲突并更新补丁与基线提交；
4. 重跑 `pnpm run build`、`pnpm --filter @deepseek-ai/dsh-client-ui-layout bundle`、`pnpm run test:gui`、`node tests/project/desktop.test.mjs`。

补丁预算：单一补丁 ≤100 行、只碰 `apps/desktop` 或通用布局；超出需用户批准。

### 19.5 升级与兼容

- v1 无数据库迁移器；升级前必须冷备份。
- 备份只能用创建它的同一版本恢复；schema 不兼容时插件会拒绝启动并提示先备份。
- 新增模块 `schemaVersion` 用 1；不要 bump 已有模块的 `schemaVersion`（会让旧库被拒）。
- 纯增量列/表可由模块 `apply` 幂等补建；非兼容 DDL 才需要迁移器。
- DSH 升级后需要重放补丁并回归：加载冒烟、客户端测试、桌面冒烟、创造流程。

### 19.6 重置数据

仅在明确要“从零开始”时执行：

1. 先冷备份（6.3）。
2. 关闭应用。
3. 把 `.studybuddy` 改名为 `.studybuddy.old-<日期>`（不要直接删）。
4. 重新启动，启动器会创建新的数据根与首次模型配置。
5. 旧 Key 不会自动从旧目录导入；需要重新填写 API Key（或设置 `STUDYBUDDY_IMPORT_CREDENTIALS` 指向旧凭据文件后首次启动）。

## 20. 常见问题与排错

### 20.1 启动与进程

| 现象 | 可能原因 | 处理 |
| --- | --- | --- |
| `pnpm` 找不到 | 安装的 pnpm 与 PATH 不一致 | 用 `pnpm --version` 确认 11.x；nvm 安装的可直接用其 `pnpm.exe` 完整路径 |
| 启动即报 `source/.env` | 旧凭据文件还在 | 把 Key 移到项目模型设置，删除/移走 `source/deepseek-harness/.env` |
| 窗口闪退，退出码 `2147483651`/`0x80000003` | 工作区目录树完整性标签被改回 Low | 管理员 PowerShell 运行 `icacls "<项目根目录>"`，确认输出中的完整性标签为 `Medium`；修复后重试启动。这是 Windows ACL 状态问题，不是应用缺陷 |
| `electron --version` 打印 v24.21.0 | 环境里有 `ELECTRON_RUN_AS_NODE=1` | `Remove-Item Env:ELECTRON_RUN_AS_NODE` 后再判断 GUI |
| 端口被占用 | 固定端口冲突 | 本项目启动器会自动选空闲端口；若手工用上游命令，设置 `DSH_DESKTOP_MAIN_INSPECT_PORT`、`DSH_DESKTOP_RENDERER_DEBUG_PORT`、`DSH_DESKTOP_HOST_INSPECT_PORT` |
| 窗口关了进程还在 | Electron 残留 | `Get-Process electron`；必要时 `taskkill /IM electron.exe /F` |
| 启动很慢 | 首次准备独立运行时 | 等几分钟；第二次启动应明显变快 |

### 20.2 模型与对话

| 现象 | 可能原因 | 处理 |
| --- | --- | --- |
| 欢迎页没有账号登录 | 设计如此 | 直接用「添加 API Key」或「稍后配置」 |
| 对话报 401/403 | Key 无效、额度不足、接口地址错 | 设置 → 模型，检查 Key 与 Base URL；重新保存 |
| 对话一直无回复 | 网络/代理/模型服务异常 | 检查网络；看宿主日志；换模型或稍后重试 |
| 重启后思考档位变了 | 首次默认 High，之后应保留 | 若被改回，检查 `home/profiles/desktop/cordis.patch.yml` 是否被手工替换 |
| 设置里改了模型不生效 | 会话仍用旧默认 | 新会话/下一轮才生效；确认默认模型已切换 |
| 换机器后 Key 不能用 | DPAPI 只能原用户解密 | 重新填写 Key；不要复制 `credentials.dpapi` 期待可解密 |

### 20.3 学习页

| 现象 | 可能原因 | 处理 |
| --- | --- | --- |
| “无法连接学习服务” | 宿主未就绪/插件加载失败 | 等启动完成；重启；看日志与「今日」页模块列表 |
| 页面一直加载 | 路由/宿主异常 | 「重试」；重启；检查 `loader-smoke` |
| 创建计划后没有任务 | 草案未确认；或未刷新 | 计划页确认；刷新工作台 |
| 助手规划后页面没变 | 页面不自动轮询 | 点「刷新」 |
| 计划页看不到草案 | 草案属于别的会话/计划 | 在创建页刷新；确认目标的当前计划 |
| 工作台没有今日计划 | 计划未确认、日期不是今天、或任务被删 | 检查计划日期与确认状态；刷新 |
| 时间块拖不动 | 触屏/浏览器事件不支持 | 用鼠标；或直接编辑时间块 |
| 保存提示修订过期 | 别处已写入 | 「重新提交」或「放弃」，不要强行覆盖 |
| 学习页入口消失 | 宿主插件未加载或被策略禁用 | 重启；看日志与「今日」页模块列表；确认 `home/cordis.patch.yml` 未被改动 |
| 英文界面出现中文 | 服务端文案/摘要仍是中文 | 已知限制；正文数据不翻译 |

### 20.4 提醒、计时与复盘

| 现象 | 可能原因 | 处理 |
| --- | --- | --- |
| 到点没有提醒 | 应用关闭/提醒关闭/静默/专注中/块无关联任务/固定块 | 检查提醒设置与时间块；提醒只在运行时生效 |
| 重启后旧提醒没出现 | 设计不补发 | 直接看工作台；需要时手动记录 |
| 提醒重复弹 | 多个块指向同一任务/旧账本未过期/重复点击 | 同一块只问一次；检查时间块是否重复；必要时重启让旧卡过期 |
| 系统通知不显示 | 权限拒绝/系统专注助手/Windows toast 限制 | 用应用内横幅；在提醒页重新授权 |
| 番茄钟重启后变“已中断” | 应用关闭/休眠超过心跳阈值 | 「继续（跳过中断）」或「结束并记录」；中断时间不计入 |
| 番茄结束任务没完成 | 设计如此 | 到工作台/计划页记录进度 |
| 晚间复盘按钮不可用 | 未到时间/提醒关闭/没有可调整条目 | 手动「现在复盘」；检查计划与进度 |
| 复盘保存失败 | 草案未确认/计划未确认/容量/依赖/修订冲突 | 按提示先确认或调整；重试 |

### 20.5 数据与备份

| 现象 | 可能原因 | 处理 |
| --- | --- | --- |
| 备份退出码 3 | 应用仍在运行 | 关闭窗口、确认无 electron，再重试 |
| 备份退出码 5 | 复制期间源数据变化 | 关闭应用后重做 |
| 备份退出码 4 | 校验/数据库完整性失败 | 不要使用这份备份；换一份或重做 |
| 恢复提示 target_not_empty | 目标非空且没 `--force` | 确认目标后加 `--force`（会先改名旧数据） |
| 恢复后数据对不上 | 版本不匹配/恢复失败 | 停应用，保留 `.pre-restore-*`，用同版本备份重试 |
| 导出被拒绝 | 文本里疑似凭据 | 删除/改写 `sk-…`、`Bearer …` 等文本后重试 |
| 数据库 schema 不兼容 | 用旧程序打开了新库 | 用创建数据的同一版本；先备份，不要手工改 schema |
| `launch.json` 让脚本误判 | pid 被复用 | 确认应用已关闭后移走旧 `launch.json`，再备份 |

### 20.6 创造模式

见 18.5。补充：

- 插件页关闭 Creator bundle 后，启动器不会强行加回；要恢复：删除 `<数据根>/home/.studybuddy-creator-enabled` 后重启，或在插件页重新打开。
- 生成的插件源码在 `<工作区>/.dsh-created-plugins/<id>` 与 profile 的 `created-plugins/<id>`；Undo 不会删源码。

| 退出码 | 含义 | 处理 |
| --- | --- | --- |
| 0 | 成功 | — |
| 2 | 参数或数据根不合法 | 按提示改 `--data-dir`/`--out` |
| 3 | 检测到应用仍在运行 | 关闭应用后重试 |
| 4 | 备份校验或数据库完整性失败 | 不要使用这份备份 |
| 5 | 复制期间源数据变化 | 关闭应用后重做 |

### 21.3 术语表

| 术语 | 含义 |
| --- | --- |
| 数据根 | 存放 profile、study.db、工作区、日志的目录，默认 `.studybuddy` |
| 草案 | 未确认的计划内容，不改变正式安排 |
| 正式修订 | 已确认并生效的计划快照，编号递增，不可变 |
| 试行 | 超容量或重叠时显式接受的计划，带复查日期与风险 |
| 待确认 | 助手记录但未核实的进度，不算完成 |
| 未记录 | 没有任何进度记录；不等于没学习 |
| 固定课程 | 课程/休息块，不计入学习分钟与完成量 |
| 项目 | 计划内的任务分组（练习册/章节/课程/复习/其他） |
| 问答单元 | 围绕一次提问（1–3 道题）的回合集合 |
| 学习日 | 本地 04:00 到次日 04:00 |
| 讲解契约 | 由画像参数编译、注入对话的讲解偏好说明 |
| 冷备份 | 应用关闭后对数据根做的字节副本 |
| JSON 导出 | 只读、可读的学习数据快照，不是可恢复镜像 |
