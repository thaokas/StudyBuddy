# 修复组 3：事实可信

> 新会话先读本说明，再只读并执行其中一张任务卡。不要一次修多张卡。

## 这一组解决什么

让计划、成果和导出都建立在可核对的事实上：期限和容量不撒谎，页码/题号不凭空出现，完成率不靠取消凑数，导出不误报成果。

## 任务卡与顺序

1. [SB-09 期限、固定块和完整工作量进入容量判断](tasks/09-deadline-capacity.md) —— 依赖 SB-01。
2. [SB-10 页码/题号必须有证据或标未核实](tasks/10-locator-evidence.md) —— 依赖 SB-01；与 SB-09 都改 `plans.mjs`，串行做。
3. [SB-12 完成率三口径统一与个人里程碑](tasks/12-completion-rate-and-milestones.md) —— 依赖 SB-01；可与 SB-13 并行。
4. [SB-13 导出使用真实成果服务并提供入口](tasks/13-export-outcomes.md) —— 依赖 SB-01；可与 SB-12 并行。

建议顺序：**SB-09 → SB-10 →（SB-12、SB-13 并行）**。

## 完成这一组的标志

- 超过考试期限/固定块占用的安排不再显示 `fits`，必须给风险或试行确认。
- 没有材料证据的页码/题号显示“待核实”，不伪装成已核实。
- 工作台和成果页使用同一三口径：原计划、调整后、主动取消；取消不提高原计划完成率。
- 导出包含真实成果或明确说明只导出原始事实；不再误报“成果模块不存在”。
- 个人里程碑只在真实 confirmed done 记录上点亮（若本轮保留该功能）。

## 不要做

- 不做公开院校信息联网入库（T08 明确不做）。
- 不做原始会话/附件导出、热备份、云同步。
- 不自动降低用户目标；只报告风险与选项。
