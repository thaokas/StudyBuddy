## 1. 问题

- 计划可以存任意日期的完整条目，但没有“阶段/周目标 + 未来 7 天详细 + 更远只留工作量”的滚动细化机制。
- 没有每日开始前把当天任务细化到可执行程度的触发/动作。
- 计划条目只有一个 `estimateMinutes`，没有学习/练习/订正/休息拆分；没有用实际记录校准估算。
- `study_plan` 只有读/草案/确认/修订/撤销，没有“只细化今天/本周”的动作。

## 2. 当前证据

- `plans.mjs` 没有 horizon/7 天概念；`items` 可任意日期。
- 没有 `refine` action；没有每日触发。
- 估算只用 `estimateMinutes`；outcomes/计时记录没有回写到估算建议。
- 静态确认见 issue 18、14。

## 3. 正确业务逻辑

1. **滚动窗口**：保存完整阶段/周目标；当前周和未来 7 天保留详细条目；更远日期只保留目标和工作量，不生成虚假的每日细节。
2. **窗口可配置**：默认 7 天，但允许学生/设置调整；不要把 7 天写成不可变要求。
3. **`refine` 动作**：`study_plan refine` 只细化指定日期/本周，不重写全部历史；带 `baseRevision` 和 `requestId`。
4. **每日触发**：每天首次打开/复盘时，提示“细化今天”或由确定性服务生成今日清单；失败不伪造。
5. **工作量分类**：条目记录学习/练习/订正/休息分钟；容量按总分钟。
6. **估算校准**：用实际计时/完成记录计算偏差，给出“建议估算”，保留原始估算与用户决定；不能自动改历史或目标。
7. **版本**：细化追加计划修订并保留原因；手动修改优先，过期草案不覆盖。

## 4. 修改范围

- `plans.mjs`：增加 horizon/窗口、`refine` 方法/工具动作；只改指定日期；保留阶段/周目标。
- 每日触发：启动或复盘时检查今日是否已细化；生成“今日清单”但不重复。
- 工作量分类字段；估算建议服务读取 outcomes/timer。
- `plan.js`：显示“今日需细化”“建议估算”；提供操作。
- 测试：7 天窗口、远日只留目标、refine 不覆盖手动、估算建议、每日不重复、版本冲突。

## 5. 验收标准

- [ ] 阶段目标完整保存；未来 7 天有条目；更远日期没有伪造的每日细节。
- [ ] `study_plan refine(date=today)` 只改今天，带版本/幂等；过期拒绝。
- [ ] 每日首次打开提示/生成今日清单；重复打开不重复生成。
- [ ] 学习/练习/订正/休息分钟进入容量；实际记录给出估算建议，原估算保留。
- [ ] 手动修改优先，refine 不覆盖新修订。
- [ ] `node --test --test-isolation=none plugins/study/tests/plans plugins/study/tests/outcomes` 通过。

## 6. 不做

- 不自动改考试目标/教材/每日预算。
- 不自动降低用户目标。
- 不做模型自主重排；由 Agent 提议、确定性服务校验。
