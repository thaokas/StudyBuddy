## 目标与边界

首次完成只固定 S1 并行开发所需的学习核心接口，不等待记忆/Creator/完整备份协议。先读总览/RELEASES/执行规则/依赖表、设计第 5—8 节及 B01 source-map。独占公共 contracts 区；不实现数据库、规划器或界面，不建设事件总线/工作流框架。B01/R01 不依赖本任务。

## 实施步骤

1. S1 定义学生/目标作用域、资料元数据/来源、任务、时间块、进度核实、执行记录、计时和冲突返回。保留稳定 ID 与版本语义，不提前做全部未来模型。
2. 定义 UI/后续 Agent 共用读写命令及运行时校验：请求身份、期望版本、事务、授权/冲突/验证/离线错误；S1 手动修改也必须可追溯。
3. 定义日期/时区/跨日、时长/数量单位、局部移动、固定约束、未安排工作；确定版本兼容与能力查询约定，缺失能力须显式返回不可用。
4. 定义 S1 必需的计时/生命周期/通知桥与最小写入屏障协议、fake clock/model 注入点；不实现通用调度平台。
5. 写出按阶段增补清单：C04/E02 负责提出 S2 计划/试行/撤销协议，F01/F02/F03/F04 提出 S3 记忆/跟进协议，G01/H03 提出 S4 权限/命名空间/备份参与者协议。由契约所有者审核落地，需配样例和兼容测试，不以这些未来增补阻塞本任务。
6. 为当前接口提供正向/非法输入样例和简短 ADR；用 schema 保证不可信输入不能直接写库，记录扩展流程和版本迁移要求。

## 验收

- S1 目标/任务/日程/进度/计时/生命周期接口有 schema、错误、样例和明确所有权；版本/幂等/权限不能绕过。
- 待确认不等于未完成，计时不等于任务完成；取消、部分完成和未安排量可无歧义表示。
- 未来 Agent/工具仍复用事实源；未来契约增补路径明确，但无需先完成记忆、Creator 或全量备份模型。
- 后续任务开始实现新能力前，先按流程补对应契约/mock 并过评审，不准私下读库；不能将“预留扩展清单”误报为未来接口已实现。
