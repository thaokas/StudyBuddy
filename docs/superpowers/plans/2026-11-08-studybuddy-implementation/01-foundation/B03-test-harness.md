## 目标与范围

先让 S1 插件/前端可独立验证，后续阶段按新增契约扩展测试支撑。阅读总览/RELEASES/执行规则/依赖表及 B01/B02；吸收 A01/B01 的原生 DSH 命令；R01 如已完成则复用其测试，尚在执行时稍后合入，不形成相互等待。S0 不等本任务。负责 test-support、统一测试配置/CI；不替后续模块实现生产业务。根依赖和锁文件与 B01 集成人协调。

## 实施步骤

1. 根据实际 DSH 工程选用已有测试工具，落地安装、类型检查、单测、契约、集成、前端/桌面冒烟和构建的真实命令，登记 `evidence/B03/commands.md`。
2. S1 提供临时数据根、可控时钟/时区/睡眠事件及 DSH 会话冒烟；保留模型注入点。Schedule、模型复杂响应及沙箱宿主适配由使用它们的后续任务增补，不提前建齐。
3. 为 B02 当前 S1 服务提供 mock，共用 schema 和契约测试，不复制漂移类型。D02/D04/D05 开始时由其任务与契约所有者补充各自需要的 mock。
4. 提供 S1 目标/资料/固定课程/部分完成/待确认/时间冲突/版本/跨日样例；恶意材料及受限工具 fixture 随 E/G 任务补充。
5. 设置基础 CI、脱敏日志规则、失败证据位置和无网络默认测试；区分可选真实模型/桌面测试的授权与环境要求。

## 验收

- 空插件工程能运行类型检查、一个后端契约测试和一个插件 UI 冒烟；有实际命令和结果。
- D01/D03 可用当前 mock 开发；D02/D04/D05 有明确增补方式，不能为未来未交付接口阻塞 B03。错误、版本冲突、加载/空态测试不依赖活模型。
- fake clock 可确定性覆盖暂停、睡眠与重启；测试不访问学生真实文件、不需要真实 Key。
- 每个下游知道测试放哪里、用什么命令、如何记录证据；生产未实现项不被 mock 成功掩盖。
