## 目标与输入

让用户在已可用的本地学习工具上，通过原生 DSH Agent 导入资料、协商计划并答疑，而不是把手动功能重做一遍。阅读 README/RELEASES/EXECUTION/DEPENDENCIES、直接前置及 E01/E02 服务记录。

## 文件边界

负责 `tests/releases/s2/`、接线说明和阶段证据；必要连接修改由原模块所有者落实。D02/D04、C04/E03 和 H02 复用已有插件接口；R02 手动录入保留。未来记忆/跟进/Creator 不作为依赖。

## 实施步骤

1. 将 D02 的目标/课程/资料导入、状态/来源显示接到 C02/E01；模型/凭据设置使用 H02，继承而不丢失 S0 已有配置，Key 不转存明文。
2. 接入 E02/C04 的同一草案、多轮协商、估算/来源缺口、试行风险、正式确认、差异、版本冲突及安全撤销。只在相应真实服务可用后开放工作台入口。
3. 接入 D04/E03：从任务进入答疑、可移除上下文、自由聊天及专题会话。Agent 读取 C03/C04 最新事实；memory 尚未提供时明确空召回，不用临时私有记忆库顶替。
4. 验证目标/现有课程 → 导入材料 → 协商确认 → 工作台拖拽 → Agent 读最新 → 任务答疑 → 部分完成 → 再协商修订/撤销；不依赖晚间自动复盘。
5. 覆盖超负荷知情试行、缺页码/未知年份、换书留历史、容量不足、旧提案与手动修改竞争、模型失败/重试及缺 Key 本地可用。
6. 构建当前提交运行包，回归 S0/S1，演练前一版本冷备份、迁移/重启及匹配版本回退；更新已支持模型/附件能力矩阵和数据发送说明。

## 验收

- UI/Agent 共用权威业务入口；确认前不改正式安排，保存前不宣布更新，旧草案不覆盖手动改动。
- 材料证据可追溯，模型不造章节/题号；排不下的剩余工作明确保留；撤销保留后来发生的学习记录。
- 实际 DSH 工具/会话/插件服务完成链路，不以 mock 聊天/结果代替；真实基线模型有授权冒烟记录。
- S0/S1 不回退，有当前候选包/迁移/恢复及阶段结果；跟进、记忆、Creator 未交付项继续隐藏。
