# R01：交付 S0 基础 DSH MVP

大任务：R / 递进式版本交付  
直接前置：A02、B01  
状态：TODO  
阶段：S0，建议代号 v0.1

## 目标与必读

交付一份可实际使用的 DSH 主体桌面运行包，让用户先开始聊天/使用原生能力。不等待学习业务、记忆、跟进或 Creator。阅读计划 README、RELEASES、EXECUTION、DEPENDENCIES、A01/A02/B01 交付和该提交上游构建说明。

## 输入与文件边界

- 输入：已锁定 DSH 工程、原生能力验证矩阵、独立 profile、B01 实际构建命令。
- 独占：`release/mvp/`、`tests/releases/s0/` 和本任务证据；B01 在 source-map 中落实真实路径。
- 根配置/锁文件/插件注册由 B01 集成人协调；最小品牌/入口可在本任务提出，不抢 D01 后续学习布局文件。
- 不做：B02/B03、study 数据库、学习页、计划、记忆、Schedule 业务、生成工具、完整更新系统。可以复用现有原生能力，不另造模型客户端。

## 实施步骤

1. 基于 A02 核心矩阵形成 S0 能力清单，保留原生交互，只启用实测插件/模型；禁用探针、未交付产品入口和未经验证的原生生成/执行通路。
2. 用隔离 profile 验证模型配置、聊天/流式输出/取消/错误、创建/切换会话、重启恢复、至少一个安全工具调用、附件选择/传递及插件加载。真实模型调用需授权；不支持的附件理解能力明确说明。
3. 检查 Key 的保存/外发/日志与普通文件。如果上游安全机制满足要求则复用；否则先做仅会话或 OS 保护的最小适配，登记后交 H02 继承，不能默认明文持久化。若无法满足就报告阻塞，不以 MVP 名义放宽安全。
4. 使用原生构建机制产出含运行组件的 Windows 测试运行包；干净环境无 Node/Git/包管理器可启动。不要求完整安装器/自动更新，未签名如实标注，彻底关闭上游更新源。
5. 提供启动/模型配置/数据位置/关闭与退出/已支持与未提供项说明，以及停止全部进程后的冷备份/匹配程序恢复步骤。备份默认排除凭据，在临时 profile 真实恢复一次。
6. 固定当前提交/依赖/包校验信息，随包附当前使用组件的许可证/来源，将冒烟和构建命令登记给 B03 后续吸收；B02/B03 可以同时开发，不让未来功能延迟本任务。

## 验收

- 用户拿到运行包能配置基线模型、聊天、用已声明的工具/附件、重启找回会话；保留 DSH 插件主体结构。
- 无 Key/网络失败有准确提示，不丢会话，不宣称离线模型；原 DSH 数据未被污染。
- 包/日志/聊天无 Key，未测试模块未启用，不连接上游品牌更新源；冷备份可恢复。
- 交付运行包/校验信息、真实环境/模型矩阵、命令/结果与限制。只有源码可运行而无目标环境可用产物，不算 S0 放行。
- 本任务失败只说明 S0 未放行；不能声称已实现学习伙伴。不得拿 A03/A04 未通过作为拖延原因。
