# 任务依赖与并行调度

依赖为硬前置：必须验收且代码/产物已合并可用。`—` 表示无前置。只有 A01 初始可执行。所有任务文件中的前置必须与本表一致；改变依赖要同时更新两处并由集成人确认。

任务首次交付阶段以 [RELEASES.md](RELEASES.md) 为准。首个 MVP 只走 A01 → A02 → B01 → R01；A03/A04 不再是 B01 的硬前置。发布顺序与模块依赖分开：后续阶段可提前开发，但放行必须保留上一阶段能力。

## 3. 推荐会话分配

- 集成会话：A01、B01—B03，以及公共文件变更协调；定期收敛接口与分支。
- MVP 期优先 A02 → B01 → R01；有余力再用独立会话做 A03/A04，不因它们未完成暂停 MVP。
- S1 优先三个会话：C（本地业务）、D（学习 UI）、H01（生命周期），R02 汇合。
- S2 增加 E（资料/规划/答疑）及 H02；S3 增加 F01/F02（记忆）与 F03/F04（跟进）；S4 汇合 G、成果及数据发行保障。
- 资源较少时按当前阶段关键路径推进；记忆/隔离验证可提前做，但不抢占基础 MVP 的首个可用交付。
- 同组也可以并行：C02/C03、C04/C05、D02—D05、E01/E02；必须遵守文件所有权。不能因为有多余会话就同时修改共享入口/迁移/锁文件。

## 4. 阻断处理

A02 的基础桌面/模型/对话/插件加载能力失败会阻塞 B01/R01。调度、通知或在线快照接口缺口必须登记，由对应 H/F 任务验证后才能启用，不反向阻塞未包含它们的 S0。

A03 失败只阻塞 F01/F02、S3 记忆放行和完整首版；A04 失败只阻塞 G01/G02 及完整首版。已验收的更早阶段继续可用。记录替代方案与实际代价；需要删除产品能力、放弃隔离或改成 SDK 独立前端仍须用户决定。任何阶段都不能拿未经验证的假设启用生产功能。
