# A04：验证受限个人工具的创建与隔离可行性

大任务：A / 技术路线验证  
直接前置：A01  
状态：TODO

## 目标与输入

证明用户可在 DSH 内生成、预览、保存并恢复一个小工具，且默认不会获得本机原生插件权限。读取总览/执行规则/依赖表、A01 基线、设计第 9 节、当前 DSH Creator/创建能力及插件管理实际文档/源码。

## 范围

归属 S4，允许 A01 后提前并行排风险；未完成/失败不阻塞 B01 或 S0—S3。做最小隔离宿主与创建探针，不建设通用沙箱平台。产物 `evidence/A04/`。复用上游生成/管理流程，但不默认把生成物作为进程内 Host 插件执行。

## 实施步骤

1. 验证上游生成、持久化 UI、启停、撤销/恢复能力，标明哪些流程可复用。
2. 选择一个可嵌入 DSH 的受限载体；给出威胁模型，检查 Node、文件系统、网络、父页面/Host、凭据、任意桥接和外部导航边界。
3. 制作“学习时长统计”最小工具，使用模拟的只读学习摘要和工具私有记录，通过受控消息桥通信；记录版本并在重启后恢复。
4. 用恶意样例尝试 require/文件读写/fetch/父窗口访问/伪造桥消息/未授权计划修改，证明限制来自运行机制而非提示词约定。
5. 验证停用和恢复上一可用版本。若载体达不到限制，提交替代或范围变更决定，不降级为默认无限权限运行。

## 验收

- 有正常工具和攻击样例、可复现命令、边界测试及 `isolation-decision.md`。
- 生成物不能自行获取 Node、任意文件/网络或密钥；桥接授权与调用来源可验证。
- 预览、持久化、停用、恢复真实成立；清楚区分探针与 G01/G02 的生产实现。
- 隔离失败为 BLOCKED，阻止 G01/G02 和 S4 完整首版放行；不阻止 B01、基础 MVP 或更早阶段。若需变更受限工具范围，仍须用户决定，不能降级为默认无限权限。
