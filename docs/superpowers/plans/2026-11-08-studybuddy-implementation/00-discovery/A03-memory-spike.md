# A03：验证候选记忆插件与 DSH 的真实兼容性

大任务：A / 技术路线验证  
直接前置：A01  
状态：TODO

## 目标与输入

优先验证 @restregular/dsh-memory，而不是根据 peerDependencies 判断兼容。读取总览/执行规则/依赖表、A01 基线、设计第 7 节和候选插件对应提交的文档/源码。

## 范围

归属 S3，允许 A01 后提前并行排风险；未完成/失败不阻塞 B01 或 S0—S2。锁定候选 commit/包版本；在独立数据根做兼容性矩阵和最小补丁。输出 `evidence/A03/`。不实现正式提取流水线，不同时装两个完整记忆系统，不引入向量服务。

## 实施步骤

1. 实际加载插件，验证 Host 生命周期、工具/注入/面板入口、默认模型接入与许可证。
2. 用中文 fixture 验证新增、跨会话召回、重启持久化、修订、失效、删除和相关小量检索；记录召回缺陷，不把关键词命中冒充语义检索。
3. 验证 session/project/custom scope 如何映射学生/目标/会话，确认不与原 DSH global 记忆混用。
4. 逐项定位来源字段、短期有效期、删除墓碑、提取游标、原始会话读取及压缩触发所需接口；区分候选已有能力与需要补充的能力。
5. 评估改动量：仅薄适配则记录补丁与回归；若需重写主要生命周期，提交候选比较和决策，不强行锁依赖。

## 验收

- 交付带真实结果的 `compatibility-matrix.md`、锁定版本、复现测试和必要补丁。
- 至少覆盖两个会话和一次进程重启；删除、纠正和中文检索有明确期望/实际结果。
- F01/F02 能据此知道存储、召回、提取分别由谁实现；没有把自动召回误写成自动提取。
- 无法满足关键边界时保持 BLOCKED，不能无证据写“兼容通过”。
