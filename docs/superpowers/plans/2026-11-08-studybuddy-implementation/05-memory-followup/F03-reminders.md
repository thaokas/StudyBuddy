状态：TODO

## 目标与输入

通过 DSH Schedule 及时询问进度，但不将未勾选视为未学习，也不重复轰炸。阅读总览/执行规则/依赖表、A02 Schedule 接口、B02/B03、C03。H01 未就绪时使用通知/生命周期 mock。

## 边界

独占 followup/reminders。使用 DSH 的持久化调度，不造第二个通用引擎；调度身份/发送状态按公共接口持久化，不直接改 study DB。系统通知显示归 H01，晚间重排归 F04。

## 实施步骤

1. 建立少量日内检查任务，每次触发重读激活目标、日期、时间块/最新任务状态、授权与已发送身份，简单规则不调用模型。
2. 每任务每执行时段最多一次主动询问，多项逾期合并；提供完成/部分完成/尚未完成/稍后回应操作，调用 C03 正式服务。
3. 应用内与系统通知共享提醒身份，处理已读/回应、重复点击和任务刚完成的竞态；不因通知失败重复改进度。
4. 遵守静默、频率、专注计时延后和关闭设置；延后后重读当前状态，不补发已过期问题。
5. 启动/唤醒后合并仍有意义的遗漏提醒，不逐条补历史；完全退出时不宣称会运行。无 Key 仍可询问和本地记录。

## 验收

- fake clock/调度重复触发、跨日重启、应用内+系统操作只产生正确的一次逻辑结果。
- 未勾选只置待确认/发询问，不自动记零进度；已有完成量不重复安排。
- 静默/专注/多项逾期合并和“发出前刚完成”有确定性测试。
- 提供真实 Schedule 加载冒烟及 H01/I01 接入清单；通知可达性在真实桌面补验。
