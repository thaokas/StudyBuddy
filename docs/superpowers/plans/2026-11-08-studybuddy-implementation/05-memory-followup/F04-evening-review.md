状态：TODO

## 目标与输入

复用 DSH Agent 和 Schedule，把剩余工作合理接续到以后，不制造排得下的假象。阅读总览/执行规则/依赖表、设计第 4.6/8 节、B02/B03、C04、E02、F03。

## 边界

独占 followup/review。生成提案复用 E02，提交/撤销由 C04。F02 维护钩子可暂为 mock；记忆失败不能回滚已成功的业务复盘，也不能阻止本地使用。

## 实施步骤

1. 保存可配置晚间时间和微调授权，以目标+业务日期作为逻辑作业身份；状态区分待处理/运行/待确认或待调整/失败/已提交。
2. 每次读最新进度和计划，计算剩余量与未核实假设；先预留、再移动弹性安排/拆块，通过 E02 提案与 C04 校验。
3. 严守目标、教材、固定课和时间预算边界；容量不足保留未安排项和阶段影响，用户可选择减量/延时/增加投入。
4. 提交前检查版本，手动操作优先；旧提案拒绝/重算，失败重试幂等。只有保存成功后展示摘要/撤销入口。
5. 网络/API 失败保留“待调整”；退出/睡眠恢复只补最近有意义的一次，后台可取消/让位；调用可选记忆维护并分别报告结果。

## 验收

- 部分完成只移动剩余量，未核实使用暂定块；事后确认已完成可清理重复暂定安排。
- 明日无空闲时留下明确未安排工作，不堆到下一天、不改预算、不伪造完成。
- 覆盖重排中拖拽、重复触发、提交后崩溃、模型失败、关闭授权、数日恢复和撤销保留执行记录。
- I01 可查看真实版本差异和次日安排；有 fake model/clock 的完整作业测试。
