## 目标与输入

普通学生无需安装 Node/Git/包管理器即可启动 DSH 主体的 StudyBuddy 发行版。阅读总览/执行规则/依赖表、A01/B01 版本许可清单、H02 能力矩阵、H03 备份/恢复和 D01 前端补丁。

## 边界

本任务属于 S4，继承 R01 已有测试运行包以及 R02—R04 中已合并的构建增量，补齐正式安装/发行/品牌/更新配置和发布说明，不重做第二套打包管线；实现可提前并行，不以 R02—R04 全部放行为前置，最终由 I04 汇合验证。早期阶段无需等待本任务，继续使用关闭自动更新的最小运行包。根依赖和锁文件与集成人协调。业务/数据能力仍由插件实现，不把更新逻辑扩展为业务后端。不承诺未经测试的 macOS/Linux 安装包。

## 实施步骤

1. 固定并打包 DSH、插件、运行时和 SQLite 等依赖，设置品牌、应用 ID、数据根、图标/启动入口，检查不误用上游更新渠道。
2. 在干净 Windows 环境安装、首次配置、启动/退出、离线重开和卸载；用户数据保留/删除须有清楚选择，不能误删原 DSH。
3. 配置 StudyBuddy 自己的更新来源/校验机制；无签名资源时标记未签名与系统提示，不声称已签名。记录包体积、系统要求与权限。
4. 升级前调用 H03 完整备份，验证应用/插件/schema 兼容清单，失败恢复匹配版本程序和数据；不可只回滚二进制不管新 schema。
5. 随包提供许可证/来源、版本说明、已知限制、离线/费用/后台说明，以及无真实密钥的诊断指引。

## 验收

- 干净机器无开发工具即可安装运行，模型自配且本地功能可离线使用。
- 安装/升级/恢复不污染原 DSH 数据、不接入其发布源，密钥不出现在包/日志中。
- 至少一次升级失败与匹配版本恢复的真实演练，学习记录保留；安全校验失败包不可执行。
- 交付可重现构建说明、测试安装包/校验信息、许可清单和待签名/待发布项，不把候选包称为已发布。
