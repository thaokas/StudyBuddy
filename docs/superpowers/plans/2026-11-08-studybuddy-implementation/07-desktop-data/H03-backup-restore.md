# H03：实现一致性备份、导出与安全恢复

大任务：H / 桌面与数据保障  
直接前置：C01、F01、G02、H01  
状态：TODO

## 目标与输入

完整备份必须是可恢复的一致快照，而非运行中零散文件的压缩包。阅读总览/执行规则/依赖表、B02 参与者协议、C01/F01/G02/H01；动态发现所有已注册存储，包含后续记忆提取/跟进元数据。

## 范围

独占 platform/backup 及备份/恢复插件 UI。业务库、候选记忆、原始 DSH 数据和生成工具保留各自格式。不能把修改数据库连接模式当成已冻结所有 DSH 写入。

## 实施步骤

1. 区分数据导出和完整备份；导出可选原始会话/导入文件，默认排除凭据，清楚说明哪些原文件只是引用、未被包含。
2. 注册所有持久化参与者，暂停新写入和后台任务，等待/取消在途模型与事务，刷新存储后取得业务库、记忆、DSH 数据和工具的一致快照；失败要释放屏障。
3. 写入版本/来源/文件清单与完整性校验，含 DSH/插件/schema/工具版本和被排除项；不能冻结某写入源时拒绝宣称完整备份。
4. 在临时目录预检损坏包、版本不匹配、缺文件、路径穿越/符号链接和空间不足，再安全切换；保留恢复前现场，失败可回退，不半覆盖用户数据。
5. 用一次跨业务/记忆/会话/工具修改后的快照做恢复演练；验证缺凭据时重新配置，恢复匹配应用版本的路径明确。

## 验收

- 并发记录/提取/生成时备份，要么形成一致快照，要么明确失败，不产出伪完整包。
- 恢复后任务版本、进度、墓碑/游标、会话引用、工具版本/私有数据一致，旧数据可回退。
- 覆盖导出脱敏、失败释放、损坏/恶意包、未知 schema、跨版本和中途崩溃测试。
- H04/I03 获得真实恢复命令/界面和证据；不承诺未知旧 StudyBuddy 数据迁移。
