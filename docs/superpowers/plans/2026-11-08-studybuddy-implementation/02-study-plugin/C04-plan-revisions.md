# C04：实现计划草案、修订提交与安全撤销

大任务：C / study 插件  
直接前置：C03  
状态：TODO

## 目标与输入

让对话、手动操作和自动调整都作用于同一条计划版本链。阅读总览/执行规则/依赖表、B02/B03、C01/C03 和设计计划/复盘约束。不负责模型生成提案（E02）或调度（F04）。

## 范围

独占 study/plans。数据库迁移交 C01；通过 C03/C01 事务接口修改任务/时间块，不复制其业务校验。采用足够简单的确定性校验/排布，不建设通用优化平台。

## 实施步骤

1. 实现同一草案多轮编辑、月周目标、近期滚动细化、假设/来源、正式/试行状态、风险与复盘点；确认前不得改正式执行安排。
2. 实现提案预检、差异预览、授权范围、基线版本和原子提交；校验预算、固定事项、依赖、重复/冲突与剩余量。
3. 提供有限重排操作：预留时段优先、移动弹性块、拆分执行；不能静默改考试目标/教材/固定课程/预算或删任务。
4. 容量不足时明确保存未安排工作与目标影响；待确认任务可暂定，不将未知完成量伪装成事实。
5. 实现基于最新版本的撤销修订；仅撤销可逆安排变化，后续已发生的进度保留，存在冲突时拒绝/提出新提案。

## 验收

- Agent 旧草案不能覆盖刚发生的拖拽；事务失败不留下半份新计划。
- 用户知情后可确认高风险试行计划，不能反复阻止或自动降低目标。
- 排不下的工作仍可追踪；不靠重叠时间块假装排得下。
- 覆盖多轮草案、并发提交、重试、试行、容量不足和“撤销后仍保留后续学习记录”；E02/F04 能直接调用。
