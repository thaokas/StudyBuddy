# I03：执行跨模块故障、并发与安全验收

大任务：I / 集成与验收  
直接前置：I01、I02、H03  
状态：TODO

## 目标与输入

证明应用在失败/并发下不会损坏学生事实、泄密或虚报成功。阅读总览/执行规则/依赖表、I01/I02 缺陷清单、H03 恢复协议和 B03 测试工具。

## 边界

只在隔离测试数据/凭据下进行故障注入。负责测试矩阵与复现，生产修复回原模块；需要契约修改由集成人统一管理。不是对隔离机制做绝对安全承诺。

## 实施步骤

1. 并发矩阵：拖拽 vs 晚间提交、手动完成 vs 已发提醒、重复模型工具/调度/快捷按钮、备份冻结 vs 在途提取/生成/执行记录。
2. 故障矩阵：API 失效/余额不足、网络切断、事务前后崩溃、提交成功但反馈丢失、睡眠/唤醒/退出、跨日/时区/系统时间变化、连续多日未打开。
3. 恢复矩阵：一致快照后恢复全部参与者、损坏/恶意包、版本不匹配、恢复中失败回退；检查 Key 排除与重新配置路径。
4. 安全矩阵：材料提示注入、伪造工具参数/权限、生成工具桥重放/越权/外发、日志/聊天/导出敏感信息和路径穿越。
5. 为每个缺陷建立可重复测试，修复后对原场景和相关契约回归，形成风险分级和剩余限制。

## 验收

- 过期写入被拒绝/重算，重复触发不重复业务效果；保存失败无成功摘要。
- 不虚计离线学习、不补发多天通知、不丢实际进度、不让取消伪装完成，不跨目标串数据。
- 备份恢复保留业务/记忆墓碑游标/会话/工具一致状态，失败不半覆盖；生成物无法绕开桥。
- 严重数据损坏、泄密、越权、错误恢复问题清零；未测环境/残余风险明确，不擅自豁免首版边界。
