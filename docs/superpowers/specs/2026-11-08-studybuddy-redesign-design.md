# StudyBuddy 重新设计：基于 DeepSeek Harness 的本地备考伙伴

日期：2026-11-08  
状态：已完成独立可实施性审阅，待用户审阅；产品路线已确认，具体默认值仍可调整。  
范围：产品与技术设计，不包含实现代码、安装操作或已经完成的兼容性验证。

## 1. 产品定位与已确认决定

StudyBuddy 是运行在学生电脑上的独立桌面应用。学生配置自己的模型服务和 API Key，通过对话与 Agent 共同规划备考，并使用日程、任务勾选、番茄钟等直接操作推进学习。Agent 持续了解学生，提供答疑、跟进、鼓励和计划调整。

用户已确认：

- 以考研学生为典型使用者，兼顾学习帮助和情绪支持。
- 使用 DeepSeek Harness（下称 DSH）作为核心 Agent harness；通用答疑优先复用现有模型与 Agent 能力。
- 选择独立 StudyBuddy 桌面发行版，主要通过配置、插件与界面扩展定制，尽量减少 DSH 核心改动。
- 月、周目标有弹性；每日任务具体到学科、材料和练习。时间安排可由 Agent 生成，也可手动拖拽。
- StudyBuddy 主动收集公开备考信息，接纳已有课程和计划，允许后续更换教材或练习册。
- 计划通过对话协商生成。Agent 应指出明显不合理之处；用户了解风险后仍可试行，最终决定权属于用户。
- 任务到时未勾选时询问进度；晚间根据未完成情况及时调整后续计划。
- 不建设独立的知识掌握度评估系统；从对话中积累对学生情况、状态和问题的轻量记忆。
- 优先调查并改造 DSH 原生记忆插件，而不是先建设通用记忆基础设施。
- 支持用户通过描述需求快速生成个人小插件。

本文后续的模块划分、默认频率、首发平台及范围细节是设计建议，不代表用户逐项作出了这些决定。

## 2. 成功标准与边界

第一版应让学生完成以下连续过程：说明目标并导入材料 → 协商计划 → 安排今天 → 学习与答疑 → 反馈进度 → 晚间调整 → 第二天继续。

产品价值以学生能否开始学习、计划能否持续执行、调整是否省事来判断。每日完成、每周推进和每月阶段成果都要可见；聊天时长和连续打卡天数不作为唯一成功指标。

第一版包含：

1. 本地桌面运行、用户自配 API Key、模型连接验证。
2. 资料整理与基于证据的计划协商。
3. 月周目标、日任务、时间块及拖拽安排。
4. 通用答疑、进度记录、番茄钟。
5. 任务询问、晚间复盘与后续重排。
6. 轻量跨会话记忆及查看、修改、删除。
7. 每日、每周、每月的进展反馈和简洁的成就记录。
8. 有限范围的个人插件生成、试用、持久保存、停用与恢复。
9. 本地备份、数据导出和升级恢复路径。

第一版不建设：题库平台、完整课程平台、自动能力诊断、知识图谱、多人社交、插件交易市场、自有模型服务、云端同步或全天候云端 Agent。复杂成就经济和高度拟人化关系系统也不在本轮范围内。

必须避免的结果：为操作简单功能反复聊天；用未勾选推断未学习；把一次提问永久解释为能力不足；无休止增加下一天任务；以责备或失去连续记录制造压力；插件分别维护互相矛盾的计划。

## 3. 考虑过的路线与选择

| 路线 | 收益 | 代价 | 决定 |
| --- | --- | --- | --- |
| 给现成 DSH 安装 StudyBuddy 插件套装 | 发布与维护较轻 | 学生仍需面对通用 DSH 的配置和使用界面 | 未选择，可作为内部验证方式 |
| 独立 StudyBuddy 桌面发行版，复用 DSH 并预装插件 | 安装与学习体验连贯，保留上游生态 | 需要桌面包装、产品界面和版本适配 | 用户已选择 |
| 大幅分叉 DSH，重写执行循环及工具系统 | 自由度高 | 上游同步、调试和维护成本高 | 不采用 |

默认实施方向：优先沿用 DSH 的桌面壳与 Web 应用组合，在可扩展位置添加学习工作台。品牌、启动配置和无法通过插件完成的必要窗口行为放入小范围发行版适配层。只有验证扩展点不足后，才评估 SDK 驱动独立界面；这不是第一版同时维护的第二条架构。

DSH 官方桌面采用 Electron 包装 Web 应用与本地 Host；SDK 也提供进程外控制能力。这里确认的是可复用方向，不代表已验证 StudyBuddy 所需全部界面位置。[S1]、[S2]

## 4. 从首次使用到每日学习

### 4.1 首次进入

学生完成模型连接后，Agent 通过自然对话了解考试目标、时间、当前进度和已有资源。允许先提供少量信息，再逐步完善；不要用长表单阻断进入。

可输入材料：文字、链接、本地文本/PDF、课程或教材目录截图、已有计划。第一版不要求解析整套视频课程；遇到扫描件、复杂表格或模型无法读取的附件，应明确说明并允许学生补充目录或摘录。

资料处理规则：

- 学生提供的课表和个人进度属于已知输入，但自述水平只是自述。
- 院校招生要求、考试科目等公开信息可以联网检索，保存来源、查询日期和适用年份；年份不明时不得当作当年的确定要求。
- 付费课程与个人进度由学生导入，或通过以后明确支持的授权连接获取。第一版不承诺自动登录各课程平台。
- 书目、章节、题号不足时先生成有标记的粗略任务，不能凭空补页码和题号。
- 信息不足时标注假设，只追问会明显改变安排的内容。

### 4.2 共同制定计划

Agent 综合期限、可用时间、已有课程、材料和学生要求，给出阶段目标、周目标与近期具体任务。学生继续提出修改，所有修改都作用于同一份草案。

计划采用滚动细化：保存完整阶段目标，细化当前周及近期日任务；默认精细安排未来 7 天，较远日期保留目标与工作量。每日开始前，把当天任务细化到可执行程度。7 天是可调整的设计默认值。

既有课程可标记为固定、可调整或参考；出现课程与自拟目标冲突时向学生解释，不静默替换。确认后生成正式版本，后续变更保留版本和原因。

工作量评估包含学习、练习、订正和休息。初期用学生估计或明确标注的估算，之后用实际记录修正。检查可用时间、固定事项、任务先后关系和重复安排；学科交替是可配置偏好，不声称某个统一配比对所有人都“科学最优”。

用户坚持高风险安排时允许设为试行计划。试行计划同样可执行和记录，附风险提示与复盘时点；不自动降低用户目标，不重复阻拦。

### 4.3 到达图书馆

打开后可直接查看今日任务和时间安排，并获知昨晚调整的简短摘要。对话随时可用，但查看、拖拽、勾选和计时不要求先发消息。

任务与时间块分离：任务描述“做什么”，时间块描述“什么时候做”。一个任务可以分多次执行。学生拖拽时保留任务身份和完成记录；固定课程、吃饭与休息也能占用时间，但不计为学习任务完成量。

时间冲突应立即提示。允许学生保留冲突或超负荷试行安排，但不能把一个单人日程中的重叠学习块显示为可同时完成的合理计划。拖拽默认移动所选时间块，不连带重排整天；重排整天通过明确操作或对话触发。

### 4.4 学习、答疑与计时

学生可以从任务进入答疑，自动附带任务、学科和相关材料引用；也可以自由发起与任务无关的聊天。优先复用 DSH 对话、附件及工具能力，不另造答疑 Agent。

默认有一个持续的“备考对话”用于计划、跟进和复盘；具体问题可以另开会话。多个会话共享同一备考目标的数据和相关长期记忆，避免依赖一个永远增长的聊天窗口。

番茄钟采用本地确定性计时，不调用模型。用户可调整学习/休息时长、暂停或结束，可选关联任务。计时完成不等于任务完成，也不等于知识掌握。睡眠或进程中断后的记录标记为中断，由学生确认，不把整段离线时间算作学习。

### 4.5 记录进度与轻量跟进

用户可标记未开始、进行中、部分完成、完成或主动取消。数量明确的任务可记录已完成数量；没有明确数量时允许文字说明，不强迫填写虚假的百分比。

“待确认”是进度是否已核实的标记，不是“未完成”的同义词。预计结束仍未勾选时发出询问，提供完成、部分完成、尚未完成和稍后回应等快捷操作。

默认同一任务每个计划执行时段只主动问一次，多项逾期合并提醒。学生可调整提醒、静默时段和互动语气，番茄专注期间延后普通提示。应用内记录和系统通知复用同一提醒身份，防止重复轰炸。

### 4.6 晚间复盘与自动调整

晚间时间由学生设置，建议默认 21:30。日常微调默认获得授权，用户可以关闭或撤销。

执行步骤：读取当天进度与最新计划 → 确定剩余工作 → 优先使用预留时段 → 移动弹性安排 → 检查固定约束与目标影响 → 保存调整版本 → 展示变化摘要。

自动调整的授权边界：

- 可以移动未完成工作的执行时间，拆分后续执行块，并使用既定时间预算内的弹性空间。
- 不擅自改变考试目标、教材选择、固定课程或用户设定的每日时间预算，也不静默删除任务。
- 总容量不足时，保留尚未安排的剩余工作，解释对阶段目标的影响，并提出减量、延时或增加投入的选择；不能伪造已经排得下的结果。
- 未获回应的任务保留“待确认”，对剩余量做暂定安排并标明假设；之后确认已完成时清除暂定重复块。
- 用户手动修改和 Agent 重排都基于最新计划版本；过期草案不能覆盖刚刚发生的手动修改。

完全退出、关机或睡眠时不承诺主动执行。恢复后仅补做最近仍有意义的复盘，合并遗漏提醒，不逐条补发几天的历史通知。无网络或模型不可用时保留本地记录、标记“待调整”，不展示尚未成功的重排结果。

### 4.7 成就与陪伴

完成单项任务时使用轻量反馈，不必每次弹窗或请求模型。每日、每周、每月展示已完成任务、推进的材料和学生自己的里程碑；确有记录时才描述进步，不从提问次数推断掌握度。

完成率同时区分原计划、调整后计划和主动取消，不能通过取消任务把一天伪装为全部完成。阶段反馈以鼓励和可继续的下一步为主，不使用惩罚性断签机制。

## 5. 简洁的模块结构

第一版使用本地桌面壳、本地 DSH Host 和插件，不引入远程业务后端或微服务。以下是逻辑职责，不要求拆成大量独立 npm 包。

| 模块 | 职责 | 数据归属 |
| --- | --- | --- |
| StudyBuddy 发行配置与桌面适配 | 品牌、启动、模型设置入口、后台状态、通知、更新 | 应用配置、凭据引用 |
| DSH 运行环境 | 对话、模型调用、工具执行、会话持久化、上下文管理 | 原始会话与运行记录 |
| 学习插件 study | 资料索引、目标、计划、任务、时间块、进度、番茄钟、复盘、成就 | 业务事实，唯一权威来源 |
| 记忆插件 memory | 学生偏好、近期情况、带来源的观察、召回和用户编辑 | 可修正的个性化记忆 |
| 创建能力 creator | 个人小插件需求、生成、试用、安装、停用和恢复 | 生成插件的源文件、包与版本 |

学习工作台是 study 插件的界面部分，不再单独建设一套前端数据库。提醒与鼓励也先作为 study 内部功能，以免为小功能创建过多插件。

界面与 Agent 调用相同的业务服务：读取任务、调整安排、记录进度、生成并应用计划修订。计划算法可由 Agent提出，但字段校验、时间计算、持久化、版本冲突和计时由确定性代码处理。

不依赖大量常驻 Agent。普通答疑、规划和复盘使用同一套 DSH Agent 能力及不同任务上下文；只有用户请求创建插件时才按需使用 Creator。

## 6. 数据与扩展接口

建议学习业务使用一个本地 SQLite 数据库。DSH 会话与候选记忆插件继续使用自身存储，不为了统一格式改造上游。SQLite 是当前设计选择，具体驱动留给实施者。

最小概念模型：

- **备考目标**：考试、目标学校/专业、适用年份、期限、用户时间预算。
- **资料**：课程/教材/练习册、版本、目录、本地文件或公开来源、读取与核实状态。
- **计划版本**：月周目标、任务归属、假设、用户约束、变更原因、正式或试行状态。
- **任务**：学科、材料位置、完成条件、预计工作量、前置任务、当前进度。
- **时间块**：日期、起止、关联任务、是否固定；可标记为暂定安排。
- **执行记录**：勾选、部分完成、计时、学生反馈及其发生时间。
- **复盘与变更记录**：输入版本、适用日期、修改项、遗留冲突和撤销状态。
- **里程碑**：依据已有记录计算的日周月成果，不建立独立积分经济。

任务 ID 不随拖拽、跨天重排或更换展示方式改变。换书时保留原书的完成记录，建立新任务及明确的替代关联；没有证据不能声称两本书对应题目已经完成。

写入携带版本与请求身份，重复点击、模型重试和调度补跑不会重复创建或完成任务。撤销生成新的修订，仅撤销对应安排变化，不抹去后来发生的学习记录。

为个人插件提供少量版本化接口：读取当天/本周任务、读取允许的进度摘要、创建插件自身记录、提交任务或日程变更。统一变更入口负责事实校验和历史记录。首版使用几个明确的本地事件即可，不额外建设事件总线或工作流平台。

## 7. 轻量记忆方案

### 7.1 候选与依据

首选验证 **@restregular/dsh-memory**。截至本次调查，仓库包声明为 0.30.1、MIT；支持本地 JSONL、无向量服务时的词法检索、自动召回、带有效期的状态和修订关系。[S3]、[S4]

其入口将存储、工具、注入和面板组合在一个 DSH 插件内。可先用配置减少启用功能；确需修改时，只维护明确的小范围补丁。没有通过兼容性验证之前，不把它写成最终锁定依赖。[S5]

Mindspace 作为提取机制参考：其文档说明可在压缩后用原始对话后台维护记忆；不同时装入两个完整记忆系统，不引入其全部关系与 Chat/Work 模型。[S6]

### 7.2 StudyBuddy 的记忆语义

只区分学生明确表达的信息、短期状态、Agent 的待确认观察。每条保留时间与来源；明确偏好优先于行为推测；较新的用户纠正替代旧结论。

示例：

- 明确信息：“学生希望上午优先安排数学”，关联原话。
- 短期状态：“学生今天自述疲惫”，短期有效。
- 待确认观察：“最近两次讨论了换元后的积分上下限”，关联对话；不写成“数学基础差”。

计划、真实完成量和教材目录不作为记忆副本维护；需要时读取业务服务或原始资料。删除与纠正记忆应影响后续召回，并保留删除标记防止后台提取从旧对话立即重建已删除内容。原始对话的保留/删除是独立操作，界面说明区别。

### 7.3 何时写、何时读

- 显式“记住/修改/忘掉”请求即时处理。
- 普通对话按批整理，优先在晚间复盘或会话压缩后执行。两种触发共享已处理消息位置，避免重复提取与重复费用。
- 只提取新增证据，已有记忆参与纠错和去重；按来源避免把 Agent 自己的回答当成学生事实。
- 默认使用当前配置的模型；不增加必填的第二把 API Key。后台调用有取消入口和成本可见性。
- 每次对话仅加载相关的小量记忆，设置上下文预算；原始对话通过 DSH 历史查询按需取回。
- 第一版不启用向量模型、图数据库或独立检索服务。中文关键词召回不足时，再评估向量选项。

候选插件的自动召回不等于自动提取。StudyBuddy 的学习提取规则、来源字段及删除后的抑制机制需要单独验证或补充；不应把这些需求误报为插件已经全部支持。[S7]

### 7.4 作用域

首版一个操作系统用户对应一个本地学生档案，同时允许多个备考目标，默认只激活一个。长期偏好按学生保存，材料问题和短期观察按备考目标关联，临时上下文按会话保存。

候选插件目前使用会话、项目和自定义范围；需要将其映射为上述语义，不能要求学生手动理解 DSH 工作区路径。StudyBuddy 使用独立的数据根目录和 profile，不与用户原有 DSH 的 global 记忆混用。第一版不承诺多账号共享电脑的应用内隔离。

## 8. 主动跟进与运行可靠性

DSH 官方 Schedule 已提供可持久化的定时任务，触发时投递到会话。它不是系统通知服务，因此需由桌面适配层补上通知显示；不要另造第二套通用调度引擎。[S8]

默认使用少量调度任务：日内进度检查与晚间复盘。用户未完成量及是否需要调用模型由本地业务状态决定；简单询问、提示音、番茄结束和勾选反馈无需模型。

每次触发前检查应用状态、静默设置、日期、任务最新状态与已发送记录。复盘按“备考目标 + 日期”去重；失败可重试，只有成功保存后才宣布计划已更新。

退出前说明后台工作会停止；启动时显示已恢复、待确认及待补做事项。API 失败或余额不足不影响查看计划、勾选、拖拽、计时和编辑本地记录。复盘、记忆维护与前台对话避免并发竞争同一份草案，前台操作优先。

## 9. 用户生成小插件

这项能力属于第一版的受限实验功能，不能只留一句“以后支持”。默认入口为对话中的“为我制作一个小工具”，开发术语收在详情里。

优先复用 DSH Creator、插件管理和持久化界面生成能力。官方已有创建、撤销和恢复流程，但这些机制的 StudyBuddy 集成仍需验证。[S9]

第一版支持的典型输出：学习时长图表、个人打卡记录、复习清单、简易问答小工具。已有能力可以满足时直接配置或组合，不重复生成。

流程：描述需求 → 给出具体行为和所需数据 → 学生选择生成 → 本地创建并预览 → 学生启用 → 可继续修改、停用、恢复上一可用版本。

生成插件的数据访问通过学习接口；自己的记录存到独立命名空间。修改正式计划仍经过统一业务变更入口，不能直接覆写数据库。普通记忆不具备授予新权限的效力。

必须明确：原生 DSH Host 插件可能拥有进程内能力，接口约定不等于安全沙箱。首版的一键生成体验限于受约束的界面/记录型插件，要求在无 Node、无任意文件及网络能力的隔离预览/执行环境中运行，通过受控桥接调用学习接口。复用上游的创建工作流不代表生成包天然满足这些限制。[S10]

完整的原生插件可以保留为高级安装方式，明确其本机代码权限；不能把它包装成默认安全的小工具。如果上游机制无法满足受限生成能力，先验证一个最小隔离宿主，不扩张成通用沙箱平台。若这一验证失败，需将它作为第一版范围变更交给用户决定，不能默默删去功能或改成无限权限运行。

## 10. 桌面交付、本地数据与费用

设计默认首发 Windows，接口与存储保持跨平台；macOS/Linux 安装包随后按实际验证结果提供。用户已确认本地桌面形态，但未指定首发操作系统，因此 Windows 优先是可修改的建议。

安装包包含运行所需组件，普通学生无需安装 Node、Git 或 pnpm。首次使用不要求注册 StudyBuddy 云账号。API Key 在本机配置，经凭据适配层使用操作系统保护能力保存；不写入聊天、插件代码、普通日志或默认导出包。具体凭据 API 留给实现验证。

本地保存不意味着离线推理。界面需清楚解释：调用学生配置的模型/搜索服务时，会发送相关上下文。只发送任务需要的资料片段；常规操作不因日志上传或分析服务而依赖 StudyBuddy 服务器。

提供模型连接检查、失败原因与重试；不承诺所有 OpenAI-compatible 服务完全兼容 DSH 的全部能力。首版选择一个经验证的 DSH 模型适配器作为支持基线；其他适配器按能力检查开放，不自动改用未经学生配置的付费服务。

数据导出包含业务记录、记忆和可选原始会话/导入文件，默认排除凭据。完整备份使用一致性快照：暂停后台写入，完成进行中事务，再备份业务库、记忆文件、DSH 数据及版本清单；不得把运行中的零散文件复制宣称为完整恢复点。

应用升级锁定 DSH 与插件兼容版本，升级前备份，失败可恢复匹配版本的数据。使用 StudyBuddy 自己的更新配置，不误接入上游品牌的发布渠道；保留开源许可和来源说明。未取得旧 StudyBuddy 源码与数据结构前，不承诺旧数据自动迁移。

## 11. 验证门槛与交付顺序

本节是设计验收边界，不是具体编码任务清单。实施计划在设计确认之后制定。

### A. 先确认复用成立

锁定一个 DSH 版本，验证自定义 profile、桌面品牌与本地目录隔离、学习页面扩展、模型配置和 Schedule。验证 RestRegular 的加载、跨会话读取、重启持久化、修订、删除及中文词法召回。

为候选记忆插件与当前 DSH 版本记录实际结果；包声明中的宽泛 peerDependencies 不是兼容证明。若仅适配小接口，维护薄补丁；若需重写大部分生命周期，回到候选比较，不硬绑。

同时验证受限个人插件的生成、持久化、隔离运行和恢复，避免把核心扩展承诺拖到末尾才发现不可实现。

### B. 打通每日使用过程

优先完成资料输入、对话式计划、日程直接操作、答疑上下文和任务记录，随后加入番茄钟、跟进、晚间调整和记忆提取。再完善阶段成就、个人插件入口、桌面恢复和安装体验。

### C. 用真实场景验收

| 场景 | 通过条件 |
| --- | --- |
| 首次提供目标与现有课程 | 识别固定安排，缺失信息明确，生成可协商草案 |
| 要求 7 天完成大量练习 | 解释估算与时间冲突；学生坚持后可试行 |
| 拖拽时间后询问 Agent | Agent 读取到最新安排，没有另一份聊天计划 |
| 更换练习册 | 保留历史，新增或替代任务有依据，不伪造章节题号 |
| 未勾选但实际完成 | 询问后正确记录，不重复安排已完成量 |
| 部分完成且明天无空闲 | 只处理剩余量，保留未安排工作并解释冲突 |
| 晚间重排期间手动修改 | 过期结果被拒绝或重算，不覆盖新操作 |
| 关闭窗口、退出、睡眠、断网 | 状态说明准确；恢复不刷屏、不虚计时、不重复复盘 |
| 新会话继续备考 | 相关偏好可召回；短期状态不永久化 |
| 纠正或删除一条记忆 | 后续使用新状态；旧对话后台整理不立即重建被删除项 |
| 完成日周月目标 | 呈现有依据的成果，取消任务不伪造完成率 |
| 创建一个个人统计工具 | 可预览、持久保存、停用与恢复；不能绕过受控接口修改计划 |
| 无 API Key 或服务不可用 | 本地计划操作与计时仍可用，AI 功能明确等待配置/恢复 |
| 升级失败 | 能恢复匹配的应用与数据版本，原学习记录仍在 |

## 12. 尚未验证与交给实施者的选择

未验证：具体 DSH 版本与记忆插件版本组合、界面扩展位置、凭据存储适配、通知桥接、原始对话读取接口、受限插件隔离载体、打包签名与安装体积。实施前以小范围兼容性验证回答，不把文档调研当作测试成功。

实施者可自行决定：SQLite 驱动、表与索引细节、界面组件、测试工具、模块内部文件组织、后台批处理细节和隔离预览实现，前提是不改变已确认的用户流程与数据/权限边界。

需用户审阅的设计默认值：Windows 首发；当前周/未来 7 天精细规划；21:30 建议复盘时间；一名本地学生且一个当前激活目标；个人插件一键生成先限于界面/记录类。这些默认值均可调整，不应被描述成既有用户要求。

原项目的 https://github.com/thaokas/StudyBuddy 尚未成功读取，本地工作区目前没有源代码或 Git 元数据。本文不判断旧代码可复用比例；旧功能和数据迁移必须以之后取得的实际代码为依据。
