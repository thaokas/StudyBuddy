# 登录后业务页面响应式布局设计

## 背景

当前前端主要按手机纵向界面组织：共享外壳限制在较窄宽度，底部导航常驻，业务页面大多为单列卡片。这个结构适合手机和浏览器窄窗口，但在桌面宽屏、横屏平板或浏览器宽窗口中会浪费空间，也会让“创建备考计划”这类高信息密度页面缺少上下文面板。

本设计只覆盖登录后的业务页面。登录页和注册页保持现状，不纳入本次改造。

## 已确认决策

- 宽屏框架采用左侧导航工作台。
- 窄屏继续采用手机单列布局和底部导航。
- 布局切换只按视口宽度判断，不按设备 UA 或屏幕方向判断。
- 推荐断点为 `lg`，即 `1024px` 左右：小于该宽度使用窄屏布局，大于等于该宽度使用宽屏工作台布局。
- “创建备考计划”页在宽屏下使用左侧对话区加右侧信息面板。
- `Login` 和 `Register` 不改。

## 目标

- 手机、浏览器窄窗口、DevTools 手机模拟使用稳定的窄屏体验。
- 桌面宽屏、浏览器宽窗口使用更高信息密度的工作台体验。
- 业务页面根据内容性质在宽屏中拆成两栏、多栏或侧栏加主内容，而不是简单把手机页面拉宽。
- 保留现有业务逻辑、API 调用、提醒弹窗、SSE 计划创建流程和路由结构。
- 用测试锁定关键响应式行为，减少后续回归。

## 非目标

- 不重设计登录页和注册页。
- 不改变后端 API、数据结构或认证流程。
- 不引入新的 UI 组件库。
- 不重写现有页面业务逻辑。
- 不把浏览器横竖屏方向作为主要切换条件。

## 全局布局架构

共享 `Layout` 负责根据 CSS 断点呈现两套外壳：

- 窄屏外壳：保留当前移动端框架，主体内容最大宽度保持手机阅读宽度，底部五入口导航常驻。
- 宽屏外壳：页面占满可用宽度，左侧固定导航栏，右侧为主内容区域。主内容区采用最大宽度限制和舒适内边距，避免超宽屏文本行过长。

导航项沿用现有入口：首页、计划、打卡、任务、我的。宽屏左侧导航保留图标和文字，并突出当前路由；窄屏底部导航保留当前主操作按钮风格。

建议在 `Layout` 内拆出小组件：

- `MobileBottomNav`：只负责窄屏底部导航。
- `DesktopSidebar`：只负责宽屏侧边导航。
- `AppContentShell`：统一主内容区域宽度、滚动和背景。

这样可以让导航结构变清楚，也避免后续页面把全局响应式规则散落到各处。

## 页面布局

### 首页

窄屏维持当前纵向顺序：欢迎卡、当前计划、今日任务、快捷入口。

宽屏改为仪表盘：

- 左侧主栏展示欢迎卡和当前进行中的计划。
- 右侧辅助栏展示今日任务摘要和快捷入口。
- 如果没有进行中的计划，创建计划入口保持明显，避免宽屏空状态显得稀薄。

### 计划列表

窄屏使用单列计划卡片。

宽屏使用 2 到 3 列卡片网格，按可用宽度自动换行。页面顶部保留标题和新建按钮。空状态居中但不拉满过宽。

### 创建备考计划

窄屏保持现有聊天流：标题、已收集信息条、消息列表、底部输入区。

宽屏使用双栏工作台：

- 左侧为对话区，占主要宽度，包含消息列表、加载状态和输入区。
- 右侧为信息面板，展示已收集考试信息、缺失信息、搜索资料、确认卡、生成状态和生成后的计划入口。
- 右侧面板为宽屏专用，窄屏中相关卡片继续出现在聊天流里。
- SSE 状态、搜索结果、确认信息、生成任务仍由现有状态驱动，不改变数据来源。

这能让用户一边与小搭对话，一边看到计划生成上下文，不需要在长聊天记录中来回滚动。

### 计划详情

窄屏继续使用概览/任务两个 tab。

宽屏减少 tab 依赖：

- 左侧展示计划头图、进度、考试信息、督促模式和危险操作。
- 右侧展示任务列表，按日期分组。
- 任务完成操作保持在任务项内。
- 切换督促模式的弹窗在宽屏下居中呈现，在窄屏下可继续使用底部弹层。

### 任务页

窄屏保持当前标题、计划选择、筛选切换和任务列表。

宽屏拆为筛选侧栏加任务主区：

- 左侧窄栏放进行中计划选择、今日/全部筛选、完成统计。
- 右侧主区展示任务列表或两列任务卡片。
- 空状态只占主区，不影响筛选区。

### 打卡页

窄屏保持当前流程：选择计划、勾选任务、填写内容、提交。

宽屏使用左右两栏：

- 左侧展示今日任务勾选和计划选择。
- 右侧展示打卡输入、提交按钮和已打卡/成功反馈。
- 已打卡状态在宽屏中也保持清晰的结果卡片，而不是拉成整页大空白。

### 提醒页

窄屏继续使用 tab 切换提醒设置、自定义提醒、提醒历史。

宽屏保留 tab，但 tab 内容利用更宽空间：

- 提醒设置中，计划/模式选择与时间配置可分列。
- 自定义提醒中，创建表单和待触发提醒列表并排。
- 提醒历史使用更宽列表，未读状态、发送状态和时间信息更易扫读。

### 报告页

窄屏保持日期选择在上、报告内容在下。

宽屏使用控制区加报告区：

- 左侧或顶部较窄区域展示日期快捷选择、自定义日期和生成按钮。
- 主报告区使用多列卡片展示等级、概览、每日进度、科目明细、AI 点评和建议。
- 表格保留横向滚动保护，避免小于宽屏断点时溢出。

### 个人页

窄屏保持头像、统计、打卡日历、操作列表顺序。

宽屏使用两栏：

- 左侧展示用户信息、统计和操作入口。
- 右侧展示最近 30 天打卡日历和补充信息。

## 响应式规则

首选使用 Tailwind 的 `lg:` 前缀表达宽屏布局，例如：

- 窄屏默认单列，`lg:grid lg:grid-cols-*` 启用宽屏网格。
- 窄屏显示底部导航，`lg:hidden` 隐藏；宽屏侧栏默认隐藏，`lg:flex` 显示。
- 计划创建页右侧信息面板默认隐藏，`lg:block` 显示。

避免使用 JavaScript 监听窗口宽度。CSS 媒体查询足够表达本需求，也更适合浏览器模拟手机、窗口拖拽和 SSR 无关的场景。

## 数据流与状态

本次改造不改变业务数据流：

- 认证、用户信息加载、提醒 WebSocket 和提醒弹窗仍由 `Layout` 和现有 store/hook 管理。
- 首页、计划、任务、打卡、报告继续调用现有 API。
- `PlanCreate` 的 SSE 事件处理、搜索结果、确认 profile、生成状态和保存计划逻辑保持不变。
- 宽屏右侧信息面板只消费现有状态，不创建新的持久状态来源。

## 错误与空状态

- 原有 loading、empty、error 文案保留。
- 宽屏空状态应限制宽度并放在主内容区域，避免铺满整屏。
- 弹窗和提醒不应被宽屏侧栏遮挡；宽屏固定元素需要明确 `z-index` 层级。
- 移动端底部安全区继续使用 `safe-bottom`。

## 测试计划

新增或更新前端测试，至少覆盖：

- `Layout` 同时包含窄屏底部导航和宽屏侧边导航的响应式类。
- 登录/注册路由不依赖共享 `Layout`，因此不受业务页面外壳改造影响。
- `PlanCreate` 在宽屏下包含聊天主区和信息面板，在窄屏下保持聊天流。
- 首页、计划、任务、计划详情、打卡、提醒、报告、个人页包含对应宽屏布局类或结构标识。

实施完成后运行：

- `npm test`
- `npx tsc --noEmit`
- 如果当前环境允许，再运行 `npm run build`

视觉验收建议使用三档宽度：

- `390px`：手机窄屏，底部导航，单列内容。
- `900px`：仍按窄屏或中间平板体验，不出现桌面侧栏。
- `1280px`：宽屏工作台，左侧导航，多列内容。

## 风险与缓解

- 风险：宽屏改造影响已有提醒弹窗或底部导航层级。
  缓解：将导航拆成独立组件，显式设置显示断点和层级。
- 风险：`PlanCreate` 文件已经较大，直接堆布局类会继续增加复杂度。
  缓解：优先抽出右侧信息面板和卡片组件，保持 SSE 逻辑原位。
- 风险：宽屏网格让卡片高度不一致，视觉显得散。
  缓解：只在适合卡片并列的页面使用网格，长文本和任务列表保持列表结构。
- 风险：当前工作区已有大量未提交改动。
  缓解：实施时只修改与响应式布局相关的文件，并在提交前逐项核对 diff。

## 验收标准

- 登录和注册页面视觉与行为不发生预期外变化。
- 小于 `lg` 宽度时，业务页面仍像手机应用：底部导航、单列内容、无左侧栏。
- 大于等于 `lg` 宽度时，业务页面呈现工作台：左侧导航、宽内容区、页面根据内容分栏。
- “创建备考计划”页宽屏时可同时看到聊天和信息面板。
- 现有测试通过，新增响应式测试通过，TypeScript 检查通过。
